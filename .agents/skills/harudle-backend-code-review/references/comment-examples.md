# 코멘트 예시

아래 상황은 설명을 위한 가상 코드다. 실제 하루들 코드에서 확인한 결함이 아니다. 파일 위치와 동작의 근거는 실제 리뷰에서 확인한 값으로 바꾼다. 예시를 맞추려고 문제나 대안을 만들지 않는다.

## 해결 방향이 분명한 문제

가정: `TokenResponse`의 `expiresIn`은 초 단위 값이다. `remaining`은 남은 시간을 담은 `Duration` 값이며, 현재는 `new TokenResponse(remaining.toMillis())`로 응답을 만든다.

**[수정 제안] 남은 시간을 초 단위로 반환하면 어떨까요?**

`expiresIn`은 초 단위인데, 코드상 `toMillis()`를 사용해서 5초가 `5000`으로 전달되는 것 같아요! 이 값을 계약대로 읽는 쪽에서는 만료 시간을 5000초로 해석할 수도 있을 것 같아요.

반환하는 값을 `toSeconds()`로 바꿔보는 것은 어떨까요?

```java
return new TokenResponse(remaining.toSeconds());
```

5초가 남았을 때 응답이 `5`인지 비교하면, 약속한 단위로 전달되는지 살펴볼 수 있다고 생각합니다.

이 경우에는 서로 다른 반환 단위를 대안으로 제시하거나 “왜 이렇게 구현했나요?”라는 질문만 남기지 않는다.

## 해결책이 여러 개인 문제

가정: 일기 목록을 한 번 읽고, 반복문에서 각 일기의 작성자를 추가 조회한다. 작성자를 모아 한 번에 읽는 방법과 목록 조회에서 함께 읽는 방법을 모두 사용할 수 있다. 실제 응답 시간의 변화는 가정하지 않는다. 이 가정은 예시를 이해하기 위한 설명이며 리뷰에 붙이는 메타정보가 아니다.

**[설계 논의] 작성자를 읽는 횟수를 줄여보면 어떨까요?**

일기가 20개일 때 목록 조회 한 번에 작성자 조회가 20번 추가가 되고 있는 거 같습니다. 목록 크기만큼 추가 조회가 생기는 N+1 Query(N+1 쿼리)에 해당할 수도 있을 것 같아요.

다음 두 방식의 **조회 횟수와 변경 범위**를 고려해서 고민해보는 것은 어떨까요?

- **작성자를 모아서 조회:** 필요한 작성자를 한 번에 읽으면 기존 일기 목록 조회를 유지하면서 총 두 번으로 읽습니다. 대신 조회한 작성자를 각 일기에 연결하는 코드가 필요합니다.
- **Join(조인)으로 함께 조회:** 목록을 읽을 때 작성자 이름까지 가져오면 한 번으로 조회합니다. 대신 목록 조회 쿼리와 반환값에 작성자 정보를 포함하도록 바꿔야 합니다.

현재 목록 조회를 유지할 수 있는 첫 번째 방법을 우선 적용해보면 어떨까요? 같은 작성자의 일기 여러 개로 반환값과 조회 횟수를 비교하면, 결과는 유지하면서 조회를 두 번으로 줄였는지 살펴볼 수 있다고 생각합니다.

여기서 줄어드는 것은 확인한 조회 횟수다. 측정 없이 응답 시간이 반드시 줄어든다고 쓰지 않는다. 실제 관계와 조회 조건에서 대안이 가능한지도 먼저 확인한다.

## 코드 품질과 선택 이유를 함께 살펴보는 경우

가정: 일기 등록과 수정의 서비스 코드에 공백 제거 및 글자 수 검사 코드가 각각 있다. 현재 요구사항은 두 기능의 저장 규칙이 같다고 명시한다.

**[설계 논의] 같은 입력 검사 규칙을 함께 관리해보면 어떨까요?**

두 기능에 검사 코드를 각각 두어서, 각 서비스 코드에서 저장 조건을 바로 읽을 수 있게 작성하신 것 같아요. 각 기능을 따로 수정하기 쉽게 하려는 선택이었을까요?

다음 **읽기 편한 정도와 규칙을 수정하는 비용**을 고려해보는 것도 좋을 거 같아요!

- **기능마다 유지:** 각 서비스 코드에서 검사 흐름을 바로 읽을 수 있지만, 같은 규칙이 바뀌면 두 곳을 함께 고쳐야 합니다.
- **공통 함수로 분리:** 규칙을 한 곳에서 수정할 수 있지만, 세부 동작을 읽을 때 함수 정의를 추가로 확인해야 합니다.

두 기능의 저장 규칙이 같으므로 공백 제거와 글자 수 검사를 공통 함수로 모아 함께 사용해보는 것은 어떨까요? 두 기능에 공백만 있는 입력을 넣어 비교하면, 같은 기준으로 저장을 막는지 살펴볼 수 있다고 생각합니다.

두 기능의 규칙이 같다는 근거가 없다면 공통화를 결론으로 정하지 않는다. 공통 함수로 옮길 코드와 각 서비스에 남길 코드를 구분해서 제안한다.
