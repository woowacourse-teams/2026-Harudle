# 문의하기

설정과 랜딩의 **문의하기**에서 `/contact`로 이동한다. 로그인이나 약관 동의에 문제가 있어도 열 수 있는 공개 화면이다.

## 접수 방식

문의는 기존 운영 메일 **harudle.official@gmail.com**로 받는다. 이미 사용하는 채널을 연결하면 별도 문의함과 발송 서버 없이 회신할 수 있다. 기존 [피드백 폼](https://forms.gle/8DMM4L835Esxk7BE6)은 의견·카테고리 건의용이며 회신 주소 항목이 없어 그대로 유지한다.

1. **메일로 문의하기**를 누르면 운영팀 주소와 문의 양식이 채워진 메일 작성 화면을 연다.
2. 사용자가 문의 종류와 내용을 적고 직접 보낸다. 문제 발생 시점은 필요한 경우에만 적는다.
3. 운영팀은 수신함에서 접수를 확인하고 해당 메일의 회신 주소로 답변한다.

메일 앱을 열었다는 사실만으로 발송이나 수신을 확인할 수 없어 서비스에서 “접수 완료”를 표시하지 않는다. 메일 앱이 없으면 **이메일 주소 복사**로 다른 메일 서비스에서 작성할 수 있다. 복사가 지원되지 않거나 실패하면 표시된 주소를 직접 선택해 복사하도록 안내한다.

이 화면은 문의 본문이나 회신 주소를 서비스 DB에 저장하지 않으며, 계정 정보·토큰·일기 내용을 메일에 자동으로 넣지 않는다. 문의에는 문제 확인에 필요한 내용만 적고, 비밀번호나 일기 원문은 보내지 않도록 안내한다.

사용자·콘텐츠 신고는 해당 콘텐츠의 더보기 메뉴에서 접수한다. 일반 문의 메일이 신고 경로를 대체하지 않는다.

<details>
<summary>운영팀 확인·회신 절차</summary>

- 운영팀이 수신함을 확인하고 문의 종류와 처리 담당자를 정한다.
- 확인에 필요한 정보가 부족하면 같은 메일 대화에서 추가로 질문한다. 비밀번호나 인증 토큰을 요청하지 않는다.
- 처리 결과를 같은 대화로 회신하고, 추가 확인이 필요한지 점검한다.
- 문의 메일의 보관·파기는 확정된 개인정보 처리 기준에 따라 진행한다. 이 기능에서 별도 보관 기간이나 회신 기한을 정하지 않는다.

</details>

## 서비스에 적용하기 전 확인

코드 검증만으로 운영팀의 실제 수신함 접근, 담당자 배정, 메일 수신·회신까지 확인된 것은 아니다. 이번 작업에서는 실제 메일이나 피드백 폼을 제출하지 않는다.

- [ ] 운영 메일을 확인할 담당자와 수신함 접근을 확인한다.
- [ ] 운영팀이 테스트 문의의 실제 수신과 회신을 확인한다.
- [ ] 모바일의 메일 앱 연결과, 메일 앱이 없는 환경의 주소 복사 경로를 확인한다.
