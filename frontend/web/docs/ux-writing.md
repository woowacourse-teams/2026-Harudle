# 하루들 UX 라이팅

명확성이 우선이고, 감성은 필요한 순간에만 담습니다. 콘텐츠 이름은 `네컷만화`로 통일합니다. 기록할 경험을 가리킬 때는 `순간`, 사용자가 입력한 글을 가리킬 때는 `내용`을 사용합니다.

## 문구 관리

화면 문구는 각 페이지의 `copy.ts`에서 관리합니다.

- [홈 문구](../src/pages/home/copy.ts): 목록, 빈 화면, 생성량 안내
- [작성 문구](../src/pages/diary-write/copy.ts): 질문, 입력 예시, 안내, 팁, 입력 오류
- [생성 문구](../src/pages/diary-generating/copy.ts): 단계별 안내, 완료, 실패, 생성 제한
- [상세 문구](../src/pages/diary-detail/copy.ts): 줄거리, 공유, 저장, 삭제

문구를 수정하면 이 문서도 함께 갱신합니다. 메타데이터는 기존 `index.html`과 `manifest.json`에서 수정합니다.

## 브랜드와 메타데이터

브랜드 소개에서는 함께 겪은 맥락을 네컷만화로 표현하고 나누는 경험을 전달합니다. 초기 사용자층인 부트캠프 교육생에 한정하지 않고 학교, 회사, 동아리 등에도 통하는 문구를 사용합니다.

| 위치                                | 최종 문구                                                         |
| ----------------------------------- | ----------------------------------------------------------------- |
| 태그라인                            | 우리끼리 통하는 네컷만화                                          |
| 브라우저 탭과 공유 미리보기 제목    | 하루들 \| 우리끼리 통하는 네컷만화                                |
| 페이지, 공유 미리보기, 설치 앱 설명 | 함께한 일상을 네컷만화로 만들고, 같이 있었던 사람들과 나눠보세요. |
| 공유 미리보기 사이트 이름           | 하루들                                                            |
| 설치 앱 이름                        | 하루들 \| 우리끼리 통하는 네컷만화                                |
| 설치 앱 짧은 이름                   | 하루들                                                            |

페이지 설명, Open Graph, Twitter Card, 앱 매니페스트에도 같은 브랜드 메시지를 적용합니다.

## 화면 문구

작성 안내는 제목 아래 12px 간격으로 가운데 정렬하고, 짧은 한 문장으로 표시합니다. 안내와 입력창 사이는 32px 간격을 둡니다. 인물 팁은 입력창 아래의 글자 수 표시 다음에 연한 라벤더 배경과 작은 ✨ 아이콘으로 묶어 표시합니다. 구체적인 외형이나 소품을 입력한 내용 속 인물 이름 옆에 적도록 안내하며, 모든 특징이 그대로 표현된다고 보장하지 않고 그림에 반영하는 데 도움이 된다고 설명합니다.

## 동작에 맞춘 사용 기준

- 입력창 위의 작성 안내에서는 공유할 순간과 개인적으로 간직할 기억 모두 적을 수 있도록 안내합니다.
- 홈의 남은 생성량은 월 선택 옆에 짧게 표시하고, 콘텐츠의 편 단위를 사용합니다. 화면에서 이미 드러나는 콘텐츠 이름은 반복하지 않습니다.
- 다른 달을 조회할 때에는 `이번 달` 대신 선택한 연도와 월을 표시합니다.
- 생성 안내 1~4단계는 3초 간격의 대기 안내입니다. 서버가 전달하는 실제 진행 단계나 완료율은 아닙니다. 완료 안내와 상세 화면 이동은 성공 응답 후에만 표시합니다.
- 생성 요청 전에 입력을 세션에 저장하고, 성공한 경우에만 지웁니다. 실패 화면에서는 입력 보존 안내와 구체적인 오류 사유를 함께 보여줍니다. 횟수 제한처럼 별도의 해결 방법이 있는 오류 사유를 숨기지 않습니다.
- 하루 생성 횟수를 모두 사용한 경우에는 즉시 다시 시도하도록 안내하지 않고 입력 보존과 제한 사유를 표시합니다.
- 현재 실패 버튼은 입력을 복원하는 작성 화면으로 이동하므로 `내용 수정하기`를 사용합니다. 동일 입력으로 바로 재시도하는 기능을 추가하면 `다시 만들기`를 사용합니다.
- 브라우저의 이미지 다운로드 동작에는 `이미지 저장`을 사용합니다. 사진 앨범에 직접 저장하는 동작이 제공될 때 `앨범에 저장`을 검토합니다.
