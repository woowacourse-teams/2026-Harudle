# 1. 2026년 08월 11일-폴더 구조

## 결정

도메인 로직과 React UI 코드를 분리하고,
UI 코드는 사용되는 Page 폴더에 최대한 co-location한다.

- `domain`: 특정 페이지에 결합되지 않는 도메인 관련 코드이다. API 요청, 도메인 타입, 도메인 유틸 함수 등이 포함된다.
- `pages`: 해당 페이지에서 사용하는 컴포넌트, Hook, State, UI 로직 등 React 및 UI관련 코드가 포함된다.
- `shared`: 여러 페이지에서 실제로 공유되는 UI나 유틸 함수 등이 포함된다.

## 이유

먼저 domain 폴더를 분리한 이유는 여러 페이지에서 같은 도메인이 사용될 수 있으므로 UI와 엮이지 않는게 좋다고 판단해서이다.

pages 폴더에는 각 페이지별로 하위 폴더가 존재하고, 각각의 페이지 폴더 안에 그곳에서만 사용되는 Hook, State를 가까이 두도록 한다.

이유는 페이지를 구현할 때 함께 수정되는 컴포넌트, Hook, State를 가까이 두어
관련 코드를 찾기 쉽게 만들고 싶었다.

다만 특정 페이지에서 여러 컴포넌트가 계층적으로 있어도 해당 페이지 폴더에서 최대 1 depth까지만 허용한다.
depth가 너무 깊어지면 수정할 부분을 찾기 힘들기 때문에 이 구조로 채택했다.

## 구조 예시

```md
src/
├─ app/
├─ domain/
│ ├─ diary/
│ └─ user/
├─ pages/
│ ├─ home/
│ ├─ diary-create/
│ └─ diary-detail/
└─ shared/
```
