# 프로필 사진 준비와 연결

기본 사진은 `public/profile-images/v1/`의 PNG 원본 10개다. 사용자가 첨부한 순서대로 번호를 정했으며 이미지를 자르거나 다시 그리지 않았다.

| 번호 | 사진     |
| ---- | -------- |
| 1    | 문어     |
| 2    | 카피바라 |
| 3    | 다람쥐   |
| 4    | 펭귄     |
| 5    | 상어     |
| 6    | 오리     |
| 7    | 거북이   |
| 8    | 박쥐     |
| 9    | 기니피그 |
| 10   | 고래     |

번호는 서버에 저장하는 값이다. 선택 화면에는 숫자를 표시하지 않고 사진만 보여준다. 파일은 Webpack 빌드에 같은 경로로 복사되며, Nginx는 없는 사진을 404로 응답한다.

## 실제 서버 연결

백엔드 PR #452와 함께 확인한다. 백엔드의 `PROFILE_IMAGE_BASE_URL`은 기존 `/profile-images/v1` 경로를 사용한다. 저장 후 조회한 사진과 선택 화면이 같은 주소를 사용하는지 확인한다.

- 로컬: `http://localhost:5173/profile-images/v1`
- 개발: `https://dev.harudle.com/profile-images/v1`
- 운영: `https://www.harudle.com/profile-images/v1`

이 변경은 파일과 설정 예시를 준비한다. 실제 서버 환경 변수 변경과 배포는 별도로 진행한다. 새 파일을 제공하는 프론트와 해당 주소를 반환하는 백엔드를 함께 확인해야 한다. 기존 번호는 유지하며 `/v1/`의 사진 파일을 이번에 정한 10개로 교체한다. 같은 주소에서 사진을 바꾸므로 Nginx는 브라우저가 파일의 변경 여부를 다시 확인하도록 `Cache-Control: no-cache`를 제공한다.

## 수정 화면과 API

사진이나 `프로필 수정` 버튼을 누르면 기존 Modal에서 사진과 닉네임을 함께 바꾼다. 바뀐 항목만 `PATCH /api/v1/me/profile`의 multipart로 한 번 보내고, 성공 응답 204 뒤 `GET /api/v1/me`로 화면을 갱신한다. 기본 이미지 번호와 개인 사진 파일은 함께 전송하지 않는다.

닉네임과 사진 오류는 해당 항목 아래에 표시한다. 파일 오류는 기본 형식 안내를 대체한다. 저장과 재조회 중에는 버튼 문구로 안내하고 중복 저장, 취소, 배경 클릭과 Esc에 의한 창 닫기를 막는다. 요청이 끝나면 다시 닫을 수 있다. 저장 전에 취소하면 변경을 버린다. 기존 Modal의 40% 배경 어둡기, 최대 높이와 내부 스크롤을 사용하며 키보드가 열린 상태에서도 내용과 버튼을 스크롤할 수 있다.

## 공통 토스트와 작업 기준

토스트 PR #451은 2026-10-23에 병합됐다. `develop-frontend`의 병합 커밋 `0d5c06c7`을 기준으로 프로필만 연결한다. 공통 Modal은 #455의 `dismissible` 옵션 변경만 가져온다. Toast, ToastContext와 인증 코드는 변경하지 않는다.

- 창이 열려 있으면 오류를 빨간 글로 표시한다. 현재 ToastProvider는 열린 dialog 위에 표시되지 않으므로 창 안 오류에는 쓰지 않는다.
- 저장과 재조회 성공 후 창을 닫고 완료 토스트를 한 번, 2초 표시한다.
- 저장 중에는 `dismissible={false}`로 창을 유지한다. 실패하면 입력을 유지하고 창 안에 오류를 표시한다.
- 저장은 성공했지만 재조회가 실패하면 입력을 잠그고 조회만 재시도한다. 저장 결과가 불확실하거나 프로필을 확인할 수 없을 때도 창 안에 재조회 안내를 표시하며, 저장 실패로 단정하지 않는다.
- 응답이 유실됐거나 결과를 확정할 수 없는 서버 오류이면 저장 성공이나 실패를 단정하지 않는다. 조회만 재시도하며, 조회 결과만으로 완료 토스트를 띄우지 않는다. 프로필 저장 전용 시간 제한이나 작업 상태 조회 API는 추가하지 않는다.
- 이전 사진 삭제만 실패한 경우 서버는 저장 성공을 유지한다. 프론트에서 저장 실패로 바꾸지 않는다.

PR은 `develop-frontend` 기준으로 프로필 변경만 포함한다.

### 비동기 생성 PR #456과의 관계

2026-10-23 확인 시 #456은 병합 없이 닫혔으며 마지막 커밋은 `6ba2fd3a`다. 이 변경은 프로필 PR에 포함하지 않는다.

- 프로필 알림은 기존 `addToast(toast, 2000)` 호출을 사용한다. #456에서 추가한 토스트 ID 지정, 갱신과 삭제는 만화 생성 알림의 책임이다.
- #456은 오래 유지하는 생성 알림을 보존하고 일반 알림을 먼저 제거한다. 프로필 완료 알림을 위해 생성 토스트를 갱신하거나 삭제하지 않는다.
- 열린 프로필 창의 오류는 창 안에 표시한다. 토스트의 z-index만 높여도 브라우저의 모달 위에는 표시되지 않는다.
- 늦게 도착한 이전 사진 조회가 새 프로필을 덮어쓰지 않도록 현재 `refreshVersion` 검사를 유지한다. 저장 중에는 `pending`으로 중복 제출을 막는다.
- #456 브랜치와 최신 `develop-frontend` 사이에는 `ToastContext.tsx`와 `e2e/diary-detail.spec.ts` 충돌이 있다. 후속 비동기 생성 PR에서 #451의 안정된 콜백과 모달 내부 삭제 오류 처리를 보존하며 합쳐야 한다. 프로필 전용 코드의 충돌과 구분한다.

## 확인 범위

API와 설정 화면 테스트에서 통합 저장, 선택 유지, 파일 검사, 재조회만 재시도, 중복 제출 방지, 저장과 재조회 중 창 닫기 방지를 확인한다. MSW의 프로필 API는 로컬 미리보기용이며 실제 이미지 변환을 하지 않는다. 실제 S3 저장, 데이터베이스 반영, 이미지 변환과 iOS 및 Android 키보드 동작은 개발 환경과 실제 기기에서 별도로 확인한다.
