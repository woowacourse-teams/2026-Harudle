# 닉네임 후보 등록을 SQL 마이그레이션으로 관리

- 작성일: 2026-10-11
- 작성자: 초록
- 상태: 채택

## 배경과 대안

최초 닉네임은 형용사와 동물을 조합하고,
중복 없이 배정해야 한다.

가입 때마다 무작위 조합을 만들면 사용 중인 조합이 늘수록 재추첨이 증가한다.

미리 생성한 후보 풀을 사용하되, Java 부트스트랩으로 등록하면 파일 로더, 생성기. 초기화 서비스가 서버에 추가된다. 초기 등록과 목록 확장은 DB 준비 작업이므로 SQL로 관리한다.

## 결정

- V21은 후보 테이블, 제약, 빈 후보 조회 인덱스를 만든다. V22는 형용사 100개와 동물 100개를 CROSS JOIN하여 후보 10,000개를 등록한다. Flyway가 각 DB에 버전별로 한 번 적용한다.
- 등록 시 신규 후보의 순서를 섞고 기존 최대 순서 뒤에 추가한다. 이미 있는 닉네임의 순서와 소유자는 덮어쓰지 않는다. 활성 회원이 이미 사용하는 후보는 그 회원의 점유를 기록한다.
- 서버에는 JSON 로더, 후보 생성기, 초기화 서비스, 부트스트랩을 두지 않는다. 적용된 SQL은 수정하지 않고, 목록 확장은 새 버전의 마이그레이션으로 추가한다.
- Java는 후보 확보, 회원 점유 기록, 점유 해제만 담당한다. 확보에는 FOR UPDATE SKIP LOCKED를 사용하고 회원 저장과 같은 트랜잭션을 유지한다.
- 사용자의 닉네임 변경은 기존 NicknamePolicy를 따른다.
