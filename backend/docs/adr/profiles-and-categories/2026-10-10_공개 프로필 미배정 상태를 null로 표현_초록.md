# 공개 프로필 미배정 상태를 null로 표현

- 작성일: 2026-10-10
- 작성자: 초록
- 상태: 채택

## 배경

기존 회원에게는 공개 프로필이 없을 수 있고, 
게스트도 같은 `users` 테이블과 `User` 생성자를 사용한다. 
두 필드를 즉시 필수로 만들면 기존 생성 경로와 데이터가 영향을 받는다.

## 검토한 대안

| 방식 | 장점 | 감수할 점 |
| --- | --- | --- |
| 즉시 필수값으로 전환 | 모든 User가 값을 가진다. | 데이터 보정과 가입, 게스트 생성 변경을 한 번에 처리해야 한다. |
| 공통 닉네임, 이미지 기본값 저장 | 빈 값을 다루기 쉽다. | 닉네임 중복이 발생하고 실제 배정과 임시값을 구분하기 어렵다. |
| 미배정을 `null`로 표현 | 기존 흐름을 유지하며 단계적으로 전환한다. | 공개 프로필이 필요한 동작에서 미배정 여부를 확인해야 한다. |

## 결정

- 컬럼의 NULL 허용과 기존 생성자를 유지한다. 이미지 코드는 `0` 대신 미배정을 표현할 수 있는 `Short`로 매핑한다.
- 실제 회원의 미배정 상태는 신규 가입 배정과 기존 회원 보정 단계에서 해소한다. 기존 `name`을 공개 닉네임의 대체값으로 사용하지 않는다.
- 게스트는 공개 프로필 배정 대상에서 제외하고, 프로필이 완성되기 전 닉네임 변경은 거부한다.

## 결과와 재검토 조건

가입 배정과 데이터 보정을 순서대로 진행할 수 있지만 미배정 상태를 처리해야 한다. 회원 보정 이후에도 게스트 때문에 `users` 전체에 NOT NULL을 바로 적용하지 않는다. 게스트의 공개 기능 참여나 계정 유형 분리 시 재검토한다.
