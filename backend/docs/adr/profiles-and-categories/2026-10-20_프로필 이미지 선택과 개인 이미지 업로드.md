# 프로필 이미지 선택과 개인 이미지 업로드

- 작성일: 2026-10-20
- 상태: 기본 이미지 변경, 개인 사진 검사와 변환, S3 저장소, 업로드 API와 DB 변경 및 이전 파일 정리 구현. 프로필 조회 응답 연결은 구현 전이다.
- 관련 이슈: [#430](https://github.com/woowacourse-teams/2026-Harudle/issues/430)

## 왜 변경하는가

현재는 회원에게 기본 이미지 5개 중 하나를 배정하고, 닉네임만 수정할 수 있다.
기본 이미지를 10개로 늘리고, 사용자가 원하는 이미지를 선택하거나 개인 사진을 올릴 수 있게 한다.
닉네임 수정과 이미지 수정은 각각 따로 저장한다.

## 정한 동작

| 항목        | 처리 방식                                                                                                                 |
|-------------|---------------------------------------------------------------------------------------------------------------------------|
| 기본 이미지 | 총 10개를 제공한다. 신규 회원은 랜덤 배정하고 기존 회원의 이미지는 유지한다.                                              |
| 이미지 수정 | 기본 이미지 10개 중 하나를 선택하거나 개인 사진을 업로드한다.                                                             |
| 닉네임 수정 | 기존 규칙과 수정 기능을 유지한다. 이미지 수정과 별도로 처리한다.                                                          |
| 업로드      | 최대 5MB의 JPEG 또는 PNG 원본을 백엔드가 받아 처리한다.                                                                   |
| 저장 형식   | WebP(웹피)로 변환해 저장한다. WebP는 이미지 파일 형식이다.                                                                |
| 이전 사진   | 새 프로필 저장이 성공하면 이전 개인 사진을 삭제한다. 변경 이력은 보관하지 않는다.                                         |
| 저장 실패   | 기존 이미지를 유지한다. 별도로 완료한 닉네임 변경에는 영향을 주지 않는다.                                                 |
| 화면 반영   | 이전 글에도 현재 프로필을 표시한다. 저장 후 피드로 돌아가면 갱신한다. 다른 사람이 열어둔 화면은 실시간으로 바꾸지 않는다. |

5MB 제한은 WebP로 변환한 파일이 아니라 사용자가 올린 원본에 적용한다.
사용자가 사진을 직접 자르는 기능은 제공하지 않는다.
서버가 사진의 가운데를 정사각형으로 자르고 저장한다. 사진을 늘려서 비율을 바꾸지 않는다.

## DB와 S3에는 무엇을 저장할 것인가

DB는 회원의 닉네임과 이미지 정보를 보관하고, S3는 실제 사진 파일을 보관한다.
다음 저장 방식을 제안한다. 아직 DB에 적용하지 않았다.

- 기존 기본 이미지 번호는 유지하고, 개인 사진의 S3 저장 경로를 추가한다. 이미지 번호의 허용 범위는 1~10으로 넓힌다.
- 개인 사진 경로가 있으면 그 사진을 보여준다. 기본 이미지를 선택하면 번호를 변경하고 개인 사진 연결을 해제한다.
- DB에는 파일의 저장 경로를 보관한다. 유효 시간이 있는 조회 주소는 저장하지 않고, 조회할 때 만든다.

기존 회원을 다시 배정하거나, 예전에 작성한 글마다 이미지 정보를 수정할 필요는 없다.
피드와 댓글에서 회원의 현재 프로필을 읽는 공통 조회 기능을 확장한다.

## 사진은 어떤 순서로 바꿀 것인가

1. 로그인한 회원인지 확인하고, 파일 크기와 실제 이미지 내용을 검사한다.
2. 사진을 WebP로 변환해 S3의 새로운 경로에 저장한다. 기존 사진은 유지한다.
3. DB가 새 사진을 가리키도록 저장한다. 닉네임은 변경하지 않는다.
4. DB 저장이 성공하면 사용하지 않는 이전 개인 사진을 삭제한다.

변환이나 업로드가 실패하면 기존 사진을 유지한다.
DB 저장 실패가 확인되면 사용하지 않는 새 파일을 정리한다.
DB 저장 결과가 불명확하면 실제로 사용 중인지 확인한 뒤 삭제한다.
S3 파일 처리와 DB 저장은 함께 되돌릴 수 없으므로 이 순서를 지켜야 한다.

이전 사진 삭제만 실패했다면 새 프로필은 유지하고 삭제를 재시도한다.
현재 사용 중인 개인 사진과 여러 회원이 공유하는 기본 이미지는 삭제하지 않는다.

삭제 대상은 `profile_image_cleanup_tasks`에 기록한다. 이전 파일의 삭제 기록은 회원 사진 교체와 같은 DB 트랜잭션에 저장한다.
커밋 후 즉시 정리를 시도하고 실패한 작업은 1분 간격으로 최대 50개씩 다시 처리한다.
정리 전 별도의 짧은 트랜잭션에서 회원을 잠금 조회한다.

진행 중인 저장이 끝날 때까지 기다리고 현재 참조 중인 파일은 삭제하지 않는다.
회원이 삭제된 뒤에도 파일을 정리할 수 있도록 삭제 작업의 회원 ID에는 외래 키를 두지 않는다.
DB 장애로 작업 기록도 남길 수 없으면 경로를 포함한 경고 로그를 남기고 기존 파일을 보존한다.

## 기존 S3 조회 방식은 어떻게 사용할 것인가

개인 사진은 기존 비공개 S3와 유효 시간이 있는 조회 주소를 사용한다.
현재 주소의 기본 유효 시간은 15분이며, `S3_ACCESS_URL_TTL` 설정을 따른다.
프로필 응답에도 만료 시각을 추가하고, 화면은 주소가 만료되면 다시 조회하도록 설계한다.
이는 다른 사람의 프로필 변경을 실시간으로 전달하는 기능과는 다르다.

기본 이미지는 기존의 고정 주소 방식을 유지하는 것을 제안한다.
저장 후 피드로 돌아갈 때 정보를 다시 조회하거나, 화면에 보관한 본인 프로필을 갱신해야 한다.

## 구현 전에 준비할 설정

- 기존 S3 버킷과 연결 객체를 재사용한다. 개인 사진은 `harudle/profile-images/{DEPLOY_ENV}/{회원ID}/{새로운UUID}.webp` 경로에 저장한다.
- 기본 이미지 파일 10개와 이미지 번호를 맞춘다. 실제 파일과 제공 경로는 구현 전에 확인한다.
- 배포용 Docker 설정에는 WebP 변환 도구인 `cwebp`가 포함되어 있다. 로컬 실행 환경에서도 이 도구를 준비한다.
- 현재 공용 업로드 제한은 파일당 20MB다. 프로필 전용 5MB 검사는 구현할 때 추가하고, 다른 업로드 기능의 제한은 그대로 둔다.

현재 사용하는 설정은 `S3_BUCKET`, `DEPLOY_ENV`, `S3_ACCESS_URL_TTL`, `PROFILE_IMAGE_BASE_URL`이다.
프로필 경로는 기존 `DEPLOY_ENV`에서 만들며 별도 환경 변수는 추가하지 않는다.
기존 S3 연결과 같이 `harudle.generation.adapters.enabled=true`일 때 프로필 저장소를 등록한다.
다른 환경이나 일기 이미지 경로는 프로필 저장소에서 삭제하거나 조회 주소를 발급할 수 없다.
저장 실패 시 예외에 보존된 파일 경로를 삭제 작업에 등록하고, 현재 사용 중인지 확인한 뒤 정리한다.
S3 요청이 뒤늦게 끝날 수 있으므로 업로드 응답이 실패한 파일은 즉시 삭제하지 않고 다음 정리 주기에 확인한다.
`POST /api/v1/me/profile-image`는 `image` 파일을 받고 성공 시 본문 없는 204를 반환한다.

## 이미지 처리 정책

| 항목                    | 결정                                                                                                                                                                                |
|-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 업로드 가능한 파일 형식 | JPEG와 PNG를 허용한다. 파일 확장자뿐 아니라 실제 파일 내용을 검사한다.                                                                                                              |
| 저장할 사진 크기        | 짧은 변을 기준으로 가운데를 정사각형으로 자른 뒤 최대 512 × 512픽셀로 줄인다. 작은 사진은 확대하지 않는다.                                                                          |
| 화면에 표시하는 방식    | 정사각형 영역을 사진으로 채우고 가운데를 기준으로 보여준다. 영역 밖의 가장자리는 보이지 않으며, 사진을 늘려 비율을 바꾸지 않는다. 기존 원형 테두리도 이 표시 영역에 적용할 수 있다. |
| 변환 품질               | 기존 변환 코드와 같은 품질 80과 압축 방식을 사용한다. 회전 보정은 하지 않으며, 위치 정보 등 원본의 부가 정보는 결과 파일에 복사하지 않는다.                                         |

예를 들어 1600픽셀 너비와 800픽셀 높이의 사진은 가운데 800 × 800픽셀을 자른 뒤 512 × 512픽셀로 저장한다.
2000 × 300픽셀의 사진은 먼저 300 × 300픽셀로 자르고 확대하지 않는다. 축소부터 해서 사진이 지나치게 작아지는 것을 피한다.
프론트엔드에서는 표시 영역의 가로와 세로를 같게 두고, `object-fit: cover`와 `object-position: center`를 적용한다.

프로필 전용 정사각형 파일 하나만 저장하며 원본은 보관하지 않는다.
사진 가장자리의 내용은 잘릴 수 있다. 업로드 전 미리보기도 같은 기준으로 표시한다.
