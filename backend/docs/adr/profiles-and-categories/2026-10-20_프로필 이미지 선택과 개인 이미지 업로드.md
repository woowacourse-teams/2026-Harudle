# 프로필 이미지 선택과 개인 이미지 업로드

- 작성일: 2026-10-20
- 갱신일: 2026-10-21
- 상태: 채택
- 관련 이슈: [#430](https://github.com/woowacourse-teams/2026-Harudle/issues/430)
- 구현과 처리 순서: [프로필 이미지 기능 설명](../../profile-image-flow.md)

## 맥락

기존에는 기본 이미지 5개 중 하나를 배정하고, 닉네임만 수정할 수 있었다.
사용자가 기본 이미지 10개 중 하나를 선택하거나 개인 사진을 업로드할 수 있도록 변경한다.
닉네임 수정과 이미지 수정은 각각 따로 저장한다.

실제 사진 파일은 저장소인 S3에, 회원이 사용하는 사진 정보는 데이터베이스인 DB에 보관한다.
S3에 저장한 파일은 DB 저장을 취소해도 자동으로 없어지지 않는다.
따라서 새 사진으로 바꾸는 중에 실패해도 기존 사진을 잃지 않는 저장 순서와 별도의 파일 정리가 필요하다.

## 결정과 이유

1. **기본 이미지 번호를 유지하고 개인 사진 경로를 추가한다.**

   개인 사진 경로가 있으면 우선 사용하고, 기본 이미지를 선택하면 개인 사진 연결을 해제한다.
   기존 회원 정보를 다시 배정하지 않고 두 방식을 함께 지원하기 위해서다.

2. **파일 검사와 변환은 백엔드에서 처리한다.**

   서버가 실제 파일을 검사하고 가운데를 정사각형으로 잘라 이미지 파일 형식인 WebP(웹피)로 저장한다.
   클라이언트가 보낸 정보만 믿지 않고 파일 형식과 저장 크기를 서버에서 통일하기 위해서다.

3. **새 파일 저장과 DB 변경이 확정된 뒤 이전 파일을 삭제한다.**

   매번 새로운 S3 경로를 사용해 DB 저장이 실패해도 기존 사진을 유지할 수 있게 한다.
   이전 파일의 삭제 작업은 사진 경로 변경과 함께 DB에 기록한다. 파일 삭제만 실패한 경우에는 사진 변경을 유지하고 삭제를 재시도한다.

4. **DB에는 저장 경로만 보관하고 조회할 때 서명 URL을 만든다.**

   서명 URL은 정해진 시간 동안 비공개 사진에 접근할 수 있는 주소다.
   주소가 만료되므로 DB에 고정해 저장하지 않고, 응답에는 만료 시각도 함께 제공한다. 기본 이미지는 기존 고정 주소를 유지한다.

5. **이전 글도 회원의 현재 프로필을 읽는다.**

   글마다 사진 정보를 복사하지 않아 변경된 사진을 다음 조회에 반영한다.
   저장 성공 후 화면에서 다시 조회하며, 다른 사람이 이미 열어둔 화면에는 실시간 변경 알림을 보내지 않는다.
   별도 실시간 처리 비용을 두지 않기 위해서다.

6. **이미지 변경 시 해당 회원의 삭제 작업을 정리한다.**

   프로필 변경 빈도가 낮아 정기 실행을 두지 않는다.
   삭제 실패 기록은 남겨두고, 해당 회원의 다음 이미지 변경에서 재시도한다.

파일 제한과 변환 설정, API 사용법, 실패 처리 순서는 [기능 설명 문서](../../profile-image-flow.md)에 기록한다.

## 결과

- **얻는 점:** 기존 회원의 기본 이미지를 유지하면서 개인 사진을 지원한다. 저장 실패 시 기존 사진을 보존하고 이전 글에도 현재 프로필을 표시한다.
- **감수할 점:** 백엔드가 파일을 받아 검사하고 변환하므로 서버 자원을 사용한다. 가운데 자르기로 가장자리가 잘릴 수 있고, 사용자가 자르는 위치를 조절할 수 없다.
- **추가로 관리할 것:** 삭제 작업과 주소 만료 후 재조회가 필요하다. 해당 회원이 이미지를 다시 변경하지 않으면 삭제 실패 파일이 계속 S3에 남을 수 있다.

## 대안

| 다른 방식 | 얻는 점 | 이번에 채택하지 않은 이유 |
| --- | --- | --- |
| 프론트엔드가 S3에 직접 업로드 | 백엔드가 파일 업로드 요청을 직접 받지 않아도 된다. | 업로드 후 실제 파일 검사와 변환을 별도로 연결해야 한다. 이번에는 백엔드가 검사부터 저장까지 처리한다. |
| 기존 S3 파일을 덮어쓰기 | 파일 경로를 고정할 수 있다. | DB 저장이 실패해도 이미 덮어쓴 원래 사진은 복구할 수 없다. |
| 원본을 저장하고 화면에서만 정사각형으로 표시 | 원본 전체를 유지하고 서버의 자르기 처리를 생략할 수 있다. | 프로필에 필요하지 않은 큰 파일도 보관하게 된다. 필요한 영역을 잘라 작은 파일 하나로 저장하는 방식을 선택한다. |
| 주기적으로 삭제 작업 처리 | 다음 이미지 변경 없이도 삭제를 재시도한다. | 실패 파일의 잔존을 허용하고, 이미지 변경 시에만 정리하기로 했다. |
