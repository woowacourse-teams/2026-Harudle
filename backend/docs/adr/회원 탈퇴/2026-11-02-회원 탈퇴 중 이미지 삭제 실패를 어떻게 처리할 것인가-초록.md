# 회원 탈퇴 중 이미지 삭제 실패를 어떻게 처리할 것인가

## 결정 (Decision)

회원이 탈퇴할 때 회원의 프로필 이미지와 일기 이미지, 이미지 백업을 삭제한다. 서비스에서 공통으로 사용하는 기본 프로필 이미지는 삭제하지 않는다.

회원 DB 기록을 삭제하기 전에 삭제할 이미지 목록을 `withdrawal_image_cleanup_tasks`에 저장한다. 목록 저장과 회원 삭제는 같은 DB 작업으로 처리하며, 하나라도 실패하면 함께 되돌린다. 이전 프로필 이미지 정리 목록도 새 목록에 옮긴 뒤 삭제한다.

회원 DB 삭제가 완료되면 기존 S3와 R2 삭제 기능을 호출한다. 삭제가 성공한 작업만 목록에서 지운다. 삭제나 목록 제거에 실패하면 탈퇴는 완료하고 목록을 유지한다.

자동 재시도와 스케줄링은 추가하지 않는다. 남은 목록은 운영자가 필요할 때 확인해 수동 정리한다. 삭제 목록은 저장소 구분, 이미지 경로와 생성 시각만 보관하고 회원 ID는 별도로 저장하지 않는다. 이미지 경로는 일반 로그에 남기지 않는다.

이미지 백업 작업과 탈퇴가 겹치는 경우를 위해 두 작업의 순서를 별도로 맞추지 않는다.

## 근거 (Rationale)

회원이 탈퇴하면 이미지를 복구하거나 별도로 활용할 필요가 없으므로 삭제한다.

처음에는 탈퇴 회원이 적을 것으로 예상해 필요한 경우 수동으로 정리하기로 했다. 하지만 실패한 경로를 남기지 않으면 정리할 파일을 찾기 어렵다. 삭제를 시도하기 전에 목록을 저장하면 회원 DB 삭제 직후 서버가 종료돼도 삭제할 대상을 잃지 않는다.

기존 프로필 정리는 회원의 다음 프로필 변경 때 다시 실행되므로 탈퇴 후에는 사용할 수 없다. 기존 이미지 조회와 저장소 삭제 기능은 재사용하고, 탈퇴용 삭제 목록만 추가한다. 탈퇴 규모를 고려해 자동 재시도는 도입하지 않고, 수동 정리에 필요한 경로를 보존한다. 외부 저장소 요청 동안 회원 삭제의 DB 작업을 유지하지 않는다.

개인 프로필 이미지 경로에는 회원 ID가 포함될 수 있다. 경로는 삭제 작업용 DB에만 보관하고, 작업이 성공하면 제거한다. 로그에는 저장소와 예외 종류만 남긴다.

백업 작업이 이미 원본을 읽은 뒤 탈퇴가 진행되는 경우는 드물 것으로 예상한다. 이 경우까지 막기 위해 백업과 탈퇴를 함께 관리하는 것보다 현재 구조를 단순하게 유지하기로 했다.

## 결과 (Consequences)

- 이미지 삭제가 실패해도 회원은 탈퇴할 수 있다.
- 삭제에 실패했거나 아직 처리되지 않은 이미지는 목록에 남는다. 자동으로 다시 삭제하지 않으며, 운영자가 저장소와 경로를 확인해 수동 정리해야 한다.
- 삭제 목록 저장이 실패하면 회원 DB 삭제도 취소된다. 소셜 연결은 그 전에 해제됐을 수 있으므로 기존 탈퇴 재시도 정책을 따른다.
- 파일 삭제 후 목록 제거 전에 서버가 종료되면 이미 삭제된 파일도 목록에 남을 수 있다. 수동 정리 시 파일이 삭제됐거나 없는 것을 확인한 뒤 해당 목록을 제거한다.
- 운영자가 정리하기 전까지 남은 이미지는 저장소에 계속 남을 수 있다. 이미 탈퇴했고 삭제 목록도 남지 않은 과거 파일은 이 변경으로 찾아내지 못한다.
- 탈퇴가 이미지를 삭제한 뒤 진행 중이던 백업 작업이 이미지를 다시 저장할 수 있다. 이때는 이미지 삭제가 실패한 것이 아니므로 삭제 실패 로그도 남지 않는다.
