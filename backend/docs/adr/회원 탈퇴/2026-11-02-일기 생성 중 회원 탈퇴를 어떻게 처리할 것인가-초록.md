# 일기 생성 중 회원 탈퇴를 어떻게 처리할 것인가

## 결정 (Decision)

일기 생성 작업의 DB 상태가 대기 중이거나 진행 중이면 회원 탈퇴를 처리하지 않는다. 작업이 성공이나 실패 상태가 되면 이 작업을 이유로 탈퇴를 막지 않는다.

| 생성 작업 상태 | 탈퇴 처리 |
| --- | --- |
| `PENDING` | 대기 중이므로 탈퇴를 막는다. |
| `PROCESSING` | 생성 중이므로 탈퇴를 막는다. |
| `SUCCEEDED`, `FAILED` | 이 작업을 이유로 탈퇴를 막지 않는다. |

## 근거 (Rationale)

탈퇴할 때 회원의 일기와 이미지를 삭제한다. 생성이 끝나기 전에 회원을 삭제하면 작업이 나중에 끝나면서 이미지가 다시 저장될 수 있다.

생성 상태를 확인한 직후 같은 회원의 새 생성 요청이 들어올 가능성은 낮다고 판단했다. 이 경우까지 막기 위해 별도의 잠금을 추가하기보다, 현재는 DB 상태만 확인해 구현을 단순하게 유지한다.

실패 상태가 된 작업은 외부 작업이 실제로 끝났는지 알 수 없어도 탈퇴를 진행한다. 회원이 실패한 작업 때문에 계속 탈퇴를 기다리는 것보다 바로 탈퇴할 수 있는 편이 낫다고 판단했다. 대신 외부 작업이 늦게 끝나거나 이미지 삭제에 실패하면 이미지가 남을 수 있다.

## 결과 (Consequences)

- 생성 작업이 대기 중이거나 진행 중인 회원은 작업이 끝날 때까지 탈퇴할 수 없다.
- 생성 요청과 탈퇴 요청이 동시에 들어오는 경우를 막기 위한 별도 잠금은 두지 않는다. 상태를 확인한 직후 새 생성 작업이 시작될 수 있다.
- 작업이 실패 상태가 된 뒤 외부 작업이 늦게 끝날 수 있다. 기존 코드는 사용하지 않는 이미지 삭제를 시도하지만, 삭제에 실패하면 이미지가 남을 수 있다.
