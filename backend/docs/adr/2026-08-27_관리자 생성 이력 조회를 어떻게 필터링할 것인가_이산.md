# 관리자 생성 이력 조회를 어떻게 필터링할 것인가

- 상태: 채택
- 작성자: 이산

## 문제

날짜 범위는 시작일을 포함하고 종료일의 다음 날을 배제하는 방식으로 변환한다. 그런데 Java의 `LocalDate`가
파싱할 수 있는 `LocalDate.MAX`(`+999999999-12-31`)를 종료일로 받으면 다음 날을 계산할 수 없어 `plusDays(1)`에서
`DateTimeException`이 발생한다. 이 값은 현재 예외 매핑만으로는 `500` 응답으로 이어질 수 있다.

## 결정

- 전체 생성 이력과 실패 이력은 하나의 `GET` API에서 선택적 필터로 조회한다.
- `userId`, `status`, `from`, `to` 조건은 함께 적용한다. `status=FAILED`를 실패 이력 조회 방식으로 사용한다.
- 날짜 범위는 `Asia/Seoul` 기준으로 시작일을 포함하고 종료일의 다음 날 0시 전까지 조회한다.
- 종료일 `to`가 `LocalDate.MAX`이면 날짜 범위 검증 오류로 처리하고 `400 VALIDATION_ERROR`를 반환한다.
- 요청 시각 내림차순, 생성 ID 내림차순으로 정렬한다.
- 명세에 없는 게스트 제외 조건은 추가하지 않고, 삭제된 일기의 생성 기록도 이력으로 조회한다.

## 이유

생성 이력과 실패 이력의 조회 조건만 다르므로 API를 분리하지 않고, 화면의 탭이 같은 조회 모델을 재사용할 수 있게 하기 위해서다.

## 결과

필터가 없는 요청은 전체 이력을 반환하고, 조건을 조합해 사용자별·상태별·기간별 조회를 지원한다. 결과가 없으면 빈 페이지를 반환한다.
