# 2026-09-30 사용량 복구 전에 생성 실패 분류를 구체화

- 상태: 방향 채택, 상세 오류 분류 미정
- 작성일: 2026-09-30
- 작성자: 이산
- 결정 대상: 그림일기 생성 실패 분류와 사용량 복구 구현 순서

## 배경

현재 `AI_PROVIDER_ERROR`에는 실제 Gemini 요청 실패뿐 아니라 일반 런타임 오류와 스토리보드 응답 처리 실패도 포함될 수 있다. 응답 처리 실패는 외부 API 로그에서 `OUTPUT_TRUNCATED`, `RESPONSE_PROCESSING_ERROR`로 구분되지만, 생성 이력에는 `AI_PROVIDER_ERROR`로 저장된다. 따라서 생성 이력만으로 실패 원인과 복구 정책을 판단하기 어렵다.

## 결정

사용 횟수 복구를 구현하기 전에 생성 실패 원인과 현재 분류 경로를 먼저 정리한다. 재시도, 복구 또는 운영 대응이 달라지는 경우에 필요한 수준으로 오류 분류를 구체화한다. 세부 오류 코드와 각 예외의 매핑은 원인 목록을 확인한 뒤 별도로 결정한다.

사용 횟수 복구는 예외가 발생했다는 사실만으로 실행하지 않고, 생성 기록이 최종적으로 `FAILED`로 확정되는 흐름과 연결한다. 복구 대상 오류와 회원·비회원 적용 범위는 분류 결과를 바탕으로 후속 결정한다.

## 이유

`AI_PROVIDER_ERROR`만으로는 429, 토큰 잘림, JSON 처리 실패, 예상하지 못한 런타임 오류를 구분할 수 없다. 오류 의미를 먼저 명확히 해야 재시도와 사용량 복구 정책을 일관되게 정하고, 실패 통계도 올바르게 해석할 수 있다.

## 결과

- 오류 발생 지점, 현재 예외 변환, 생성 이력 코드와 외부 API 진단 로그를 대응시킨다.
- 복구 정책과 무관한 세부 상태까지 생성 이력 코드로 늘리지는 않는다. 구체적인 provider 상태와 응답 진단은 로그에서 보존한다.
- 분류와 매핑을 테스트로 확인한 뒤 사용 횟수 복구 대상을 결정하고 구현한다.
- 이 ADR 자체로는 코드 동작을 변경하지 않는다.

## 재검토 조건

- 새로운 실패 유형이 확인되거나, 오류 유형에 따라 재시도·복구 정책을 다르게 적용해야 하는 경우
