# 2026-08-27 관리자 생성 가능 횟수 복구를 어떻게 원자적으로 처리할 것인가

- 작성일: 2026-08-27
- 작성자: 이산
- 결정 대상: 관리자의 오늘 생성 사용량 복구 처리

## 결정

`PATCH /api/v1/admin/users/{userId}/generation-usage/restore`는 사용량 행을 새로 만들지 않고, `used_count >= count` 조건을 포함한 단일 원자적 DB 감소 연산으로 처리한다.

- `count`는 1 이상의 정수만 허용한다.
- 대상 사용자가 없으면 `USER_NOT_FOUND`, 탈퇴 사용자면 `INACTIVE_USER`를 반환한다.
- 사용량 행이 없거나 복구 수량이 현재 사용량보다 많으면 `GENERATION_USAGE_CONFLICT`를 반환한다.
- 복구 후에도 기존 `limit_count` 스냅샷은 유지한다.
- 동시 요청은 DB 조건부 갱신 결과로 성공·충돌을 판단한다.
- 네트워크 재시도에 대한 `Idempotency-Key`는 후속 보완 항목으로 남긴다.

## 이유

애플리케이션에서 조회 후 감소하는 방식은 동시 요청 사이에 사용량이 바뀌어 0 미만으로 감소하거나 잘못된 수량이 복구될 수 있다. 조건부 원자 갱신을 사용하면 현재 사용량을 만족하는 요청만 성공시킬 수 있다.

## 결과

- 사용량 행이 없는 사용자에게 복구 요청을 보내도 DB에 임의의 사용량 행이 생기지 않는다.
- 동시에 복구 요청이 들어와도 사용량의 정합성이 보장된다.
- 같은 복구 요청이 네트워크 재시도로 중복 도착하는 문제는 아직 방지하지 않으므로 추후 `Idempotency-Key`를 검토한다.

## 재검토 조건

- 관리자 화면에서 복구 요청의 재시도 안정성이 중요해지는 경우
- 사용량 변경 이력이나 감사 로그를 도입하는 경우
