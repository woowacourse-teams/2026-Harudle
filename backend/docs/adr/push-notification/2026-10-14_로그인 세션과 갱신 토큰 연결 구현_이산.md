# 로그인 세션과 갱신 토큰은 현재 어떻게 연결되는가

이 문서는 현재 구현한 로그인 세션 저장 부분을 설명한다. 로그인 세션은 **한 번 로그인한 기록**이다. 같은 사람이 다시 로그인하면 새 세션이 생긴다.

## 로그인할 때

1. 카카오 로그인이 끝나면 서버가 `auth_sessions`에 새 행을 저장한다.
2. 서버가 Refresh Token을 만들고 `refresh_tokens.session_id`에 새 세션 ID를 저장한다.
3. 세션과 Refresh Token은 한 번의 저장 작업으로 처리한다. 둘 중 하나를 저장하지 못하면 둘 다 남지 않는다.

예를 들어 한 사용자가 크롬과 휴대폰에서 각각 로그인하면 세션이 두 개 생긴다. 두 Refresh Token은 서로 다른 세션 ID를 가진다.

## Refresh Token을 갱신할 때

서버는 기존 Refresh Token을 폐기하고 새 토큰을 만든다. **새 토큰에는 기존 토큰의 세션 ID를 그대로 저장한다.** 토큰이 바뀌어도 같은 로그인을 계속 사용한 것으로 기록된다.

이전에 발급되어 `session_id`가 없는 토큰도 있을 수 있다. 이 토큰을 갱신할 때는 새 세션을 만들고 새 토큰을 연결한다. 이미 폐기되거나 만료된 토큰은 갱신하지 않는다.

## Access Token을 발급할 때

`/auth/refresh`는 갱신한 Refresh Token의 세션 ID를 받아 Access Token에 `sid`로 넣는다. JWT의 `sub`에는 기존처럼 사용자 ID를 넣는다. `sid`는 서버가 넣고 서명하므로 브라우저가 직접 정하지 않는다.

## 로그아웃할 때

자세한 처리 순서는 [로그아웃 때 푸시 등록 정리](2026-10-14_로그아웃%20때%20푸시%20등록%20정리_이산.md)에 기록했다.

서버는 쿠키의 Refresh Token으로 현재 로그인 세션을 찾는다. 그 세션을 종료하고, 같은 세션의 유효한 Refresh Token과 푸시 등록을 해제한다. 아직 보내지 않은 `PENDING`, `PROCESSING` 작업은 `CANCELLED`로 바꾼다. 이미 전송된 `SENT` 작업과 다른 로그인 세션은 그대로 둔다. 이 변경은 한 번의 DB 작업으로 처리한다.

쿠키의 토큰이 이미 갱신되어 폐기된 상태여도 세션 ID가 남아 있다면 해당 로그인을 종료한다. 세션 ID가 없는 기존 토큰은 그 토큰만 폐기한다.

토큰 갱신과 로그아웃이 동시에 요청되면 두 요청이 같은 세션을 먼저 잠근다. 로그아웃이 끝난 뒤에는 그 세션에서 새 토큰을 발급하지 않는다. 쿠키에 Refresh Token이 없으면 서버가 어떤 세션인지 알 수 없으므로 쿠키만 지우고 응답한다.

## 지금 확인한 것과 남은 연결

DB 통합 테스트에서 세션 생성과 분리, 토큰 갱신 후 세션 유지, 세션 ID가 없는 기존 토큰의 갱신을 확인했다. Access Token의 `sid`가 DB의 세션 ID와 같은지도 확인했다. 로그아웃 시 해당 세션의 토큰, 등록, 미발송 작업이 정리되고 다른 세션은 유지되는지 확인했다.

푸시 등록 API는 아직 JWT의 `sid`를 읽어 등록에 연결하지 않는다. 발송 워커도 아직 전송 직전에 세션 상태를 확인하지 않는다. 이 두 작업이 끝나야 로그인 중인 환경에만 푸시를 보내는 흐름이 완성된다.
