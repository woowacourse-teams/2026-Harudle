# 2026-08-27 관리자 관리 대상에서 게스트 사용자를 어떻게 처리할 것인가

- 작성일: 2026-08-27
- 작성자: 이산
- 결정 대상: 관리자 사용자 관리 API의 게스트 사용자 처리 정책

## 배경

게스트 세션은 랜딩 페이지에서 한 번만 사용할 수 있는 흐름을 위해 내부적으로 `User`를 생성한다. 따라서
게스트도 `users` 테이블에는 존재하지만, 일반 사용자를 대상으로 하는 관리자 기능의 관리 대상은 아니다.

기존 사용자 검색과 상세 조회는 `guest_sessions` 연결 여부를 확인해 게스트를 제외하고 있었다. 반면 생성 사용량
복구·초기화·한도 변경은 `UserRepository.findById()`만 사용해 게스트 UUID를 직접 전달하면 작업이 수행될 수 있었다.

## 결정

게스트 사용자는 관리자 관리 대상에서 제외한다.

- 게스트 여부는 `guest_sessions.guest_user_id` 연결 여부로 판단한다.
- 생성 사용량 복구·초기화·한도 변경도 게스트를 대상으로 처리하지 않는다.
- 게스트 요청은 사용자 상세 조회와 동일하게 `USER_NOT_FOUND`(`404`)로 응답한다.
- 게스트로 판단된 경우 사용자의 한도나 오늘 사용량을 변경하지 않는다.
- 탈퇴한 일반 사용자의 기존 정책(`INACTIVE_USER`)은 유지한다.

## 이유

게스트의 `User` 레코드는 랜딩 페이지의 일회성 사용을 지원하기 위한 내부 구현이다. 이를 관리자 화면에서
변경 가능한 사용자로 취급하면 조회에서는 존재하지 않는 사용자가 변경 API에서는 유효한 대상이 된다. 관리 대상
경계를 조회와 변경 API에서 동일하게 유지하면 이러한 계약 불일치와 우발적인 정책 변경을 막을 수 있다.

## 결과

- 관리자 사용자 검색·상세 조회와 생성 사용량 변경 API의 게스트 제외 정책이 일치한다.
- `AdminGenerationUsageService`는 공통 관리 대상 사용자 조회를 통해 세 가지 변경 작업을 검증한다.
- 게스트 UUID가 전달되어도 관리자 API가 게스트의 영속 상태를 변경하지 않는다.

## 재검토 조건

- 게스트에게도 관리자 화면에서 사용량을 확인하거나 조정해야 하는 요구가 생기는 경우
- 게스트를 `User`와 별도의 계정 유형으로 명시적으로 모델링하는 경우
