# 2026-08-27 관리자 API 권한을 어떻게 검증할 것인가

- 작성일: 2026-08-27
- 작성자: 이산
- 결정 대상: 관리자 API의 접근 권한 검증 방식

## 배경

JWT는 사용자를 인증하지만, 토큰이 발급된 뒤 사용자의 권한이나 탈퇴 상태가 바뀔 수 있다. 관리자 API는 요청 시점의
사용자 상태를 기준으로 접근을 허용해야 한다.

## 결정

`/api/v1/admin/**` 요청은 공통 `AuthorizationManager`에서 다음 조건을 모두 확인한다.

- 인증된 JWT의 `sub`를 사용자 UUID로 해석한다.
- DB에서 현재 사용자를 조회한다.
- 사용자가 삭제되지 않았고 `role`이 `ADMIN`인 경우에만 허용한다.

권한의 기준은 JWT에 저장된 role이 아니라 DB의 현재 사용자 정보로 둔다. 인증되지 않은 요청은 기존 인증 진입점에서
`401 Unauthorized`, 인증은 되었지만 관리자 조건을 만족하지 않는 요청은 `403 Forbidden`으로 처리한다.

## 결과

- 모든 관리자 API에 동일한 권한 규칙을 적용할 수 있다.
- 권한 변경과 탈퇴 상태가 다음 요청부터 즉시 반영된다.
- 각 컨트롤러가 관리자 권한 검사를 중복 구현하지 않아도 된다.

## 재검토 조건

- 관리자 권한을 별도 권한 서비스나 외부 IAM에서 관리하게 되는 경우
- 요청마다 DB를 조회하는 비용을 줄여야 하는 트래픽 규모가 되는 경우
