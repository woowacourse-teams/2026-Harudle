# 2026-09-01 사용량보다 작은 생성 한도 변경을 어떻게 처리할 것인가

- 상태: 채택
- 작성일: 2026-09-01
- 작성자: 이산
- 결정 대상: 관리자 사용자별 생성 한도 변경 API

## 배경

기존에는 현재 사용량보다 작은 한도가 요청되면 오늘 사용량 스냅샷을 사용량 이상으로 보정했다. 이 경우 사용자는 남은 생성 횟수를 잃게 되므로, 한도 변경 정책을 재검토한다.

## 결정

- 새 한도가 오늘 사용량보다 작으면 `409 Conflict`와 `GENERATION_LIMIT_BELOW_USAGE`를 반환한다.
- 거절된 요청은 사용자 한도와 오늘 사용량 스냅샷을 변경하지 않는다.
- 새 한도가 오늘 사용량과 같거나 크면 변경을 허용한다.
- 오늘 사용량 기록이 없으면 사용자의 한도만 변경하고 사용량 행은 만들지 않는다.

## 이유

관리자가 한도를 낮추는 과정에서 사용자가 이미 확보한 남은 생성 기회를 자동으로 잃지 않도록 한다. 또한 변경을 조용히 보정하지 않고 명시적으로 거절해 관리자가 현재 사용량을 확인한 뒤 다시 결정할 수 있게 한다.

## 기존 ADR과의 관계

이 결정은 `2026-08-27_사용자별 생성 한도를 오늘 사용량에 어떻게 반영할 것인가`와 `2026-08-27_관리자 조회와 생성 사용량 연산의 JPA 접근 방식을 어떻게 선택할 것인가`에 정의된 “사용량 이상으로 한도를 보정”하는 부분을 대체한다. 사용자 행 잠금, 오늘 스냅샷, 초기화와 과거 사용량 보존 규칙은 유지한다.
