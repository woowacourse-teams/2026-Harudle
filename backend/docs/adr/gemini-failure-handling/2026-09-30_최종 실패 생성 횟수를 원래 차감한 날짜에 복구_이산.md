# 2026-09-30 최종 실패 생성 횟수를 원래 차감한 날짜에 복구

- 상태: 채택
- 작성일: 2026-09-30
- 작성자: 이산
- 결정 대상: 최종 실패한 그림일기 생성의 일일 사용량 복구 날짜

## 배경

생성 횟수는 사용자와 사용량 날짜별로 차감된다. 생성 실패가 즉시 확정되지 않고 스케줄러에 의해 나중에 `FAILED`로 처리되면, 차감 날짜와 실패 확정 날짜가 달라질 수 있다. 실패 확정 시점의 오늘 사용량을 복구하면 원래 차감된 날짜가 아닌 다른 날짜를 변경할 수 있다.

## 결정

- 생성 요청이 차감한 사용량 날짜(`usageDate`)에 복구한다. 이 날짜는 일기 날짜가 아니라 생성 횟수를 실제 차감한 서비스 기준 날짜다.
- 실패 확정 날짜가 다음 날 이후여도 원래 `usageDate`의 사용량을 1회 복구한다. 다음 날짜에 추가 횟수를 지급하지 않는다.
- 현재 생성 흐름에서 기술적 실패로 기록이 처음 `PROCESSING`에서 `FAILED`로 전이될 때 복구한다. 이미 실패한 기록의 재처리로 중복 복구하지 않으며, 성공한 생성은 복구하지 않는다.

## 이유

- 실패 처리가 지연되거나 자정을 넘겨도 복구 대상 날짜가 스케줄러 실행 시각에 좌우되지 않는다.
- 실패한 시도를 해당 날짜의 일일 사용량에서 제외해 과거 사용량 기록을 바로잡는다.
- 복구를 현재 날짜의 추가 한도로 바꾸지 않아 날짜별 생성 한도를 유지한다.

## 결과

- 생성 횟수를 차감할 때의 `usageDate`를 생성 기록과 연결해 보존해야 한다.
- 자동 복구는 복구 시점의 오늘 날짜가 아니라 저장된 `usageDate`를 사용해야 한다. 기존 `restoreTodayUsage`를 그대로 사용하지 않는다.
- 비회원의 1회 체험 복구는 이 ADR의 범위에서 제외한다. 랜딩페이지의 1회 체험 제공을 언제까지 지속할지 팀에서 결정되지 않았으므로, 제공 정책이 정해진 뒤 별도로 논의한다.

## 재검토 조건

- 일일 한도 정책이나 사용량 날짜의 기준 시간대가 변경되는 경우
- 랜딩페이지의 비회원 1회 체험 제공 정책이 결정되는 경우
