# 2026-10-26 생성 실패 원인과 다음 행동을 사용자 응답에 제공

- 상태: 채택 (백엔드 반영, 프론트 작업 전)
- 작성일: 2026-10-26
- 관련 작업: [PR #416](https://github.com/woowacourse-teams/2026-Harudle/pull/416), [이슈 #434](https://github.com/woowacourse-teams/2026-Harudle/issues/434)

## 배경

기존에는 내부 오류만 세분화하고 사용자 응답은 기존 코드를 유지했다. 이제는 사용자도 실패 원인을 구분하고 다음에 할 행동을 알 수 있도록 응답을 세분화한다.

## 결정

- 백엔드는 오류 코드와 사용자 행동 안내 문구인 `action`을 제공한다. 상태 조회의 최종 실패와 생성 오류 응답에 같은 기준을 적용한다. 성공 및 진행 상태의 `action`은 `null`로 반환한다.
- `action`은 “잠시 후 다시 시도해 주세요.”처럼 화면에 표시할 한국어 문구다. 버튼 동작이나 이동 경로를 지정하는 값이 아니다.
- 프론트는 `action`을 그대로 텍스트로 표시한다. 안내 문구는 백엔드에서 관리하며, 프론트에 오류 코드별 문구 목록을 따로 만들지 않는다. `action`이 없거나 잘못된 형식이면 기존 일반 안내를 표시한다.
- `action`은 사용자에게 필요한 상황 설명과 다음 행동을 담고, `GenerationErrorAction`에서 문구와 회원 및 게스트별 선택을 관리한다. `ErrorType`은 오류 코드와 HTTP 상태, 기본 설명을 관리한다. 서버 설정이나 응답 처리 방식 같은 기술적인 설명은 제외한다. 콘텐츠 차단에는 내용 수정, 연결 실패에는 잠시 후 재생성, 설정 문제에는 나중에 다시 이용하도록 안내한다.
- 일일 한도 초과는 내일 생성, 생성 중인 요청은 완료 대기, 요청 키 충돌은 기존 결과 확인을 안내한다. 요청 키 형식 오류와 생성 기록 조회 실패, 게스트 세션 오류에도 각각 안내 문구를 제공한다.
- 접수된 게스트 생성이 실패하면 체험을 복구하지 않고 로그인을 안내한다. 콘텐츠 차단은 내용을 바꾼 뒤 로그인해서 생성하도록 안내한다.
- 최종 실패 후 새로 생성할 때는 새 `Idempotency-Key`를 사용한다. 접수 여부를 확인하는 재전송에는 기존 키를 사용한다.
- 사용자에게 외부 AI 응답 원문이나 내부 설정값을 노출하지 않는다.

## 오류별 사용자 행동과 실제 안내 문구

`action`에는 사용자가 이해해야 할 상황과 다음 행동을 담는다. 요청이 많은 상황, 시간 초과, 콘텐츠 차단, 체험 소진은 설명하되 서버 설정이나 응답 파싱 같은 기술적인 원인은 넣지 않는다. 오류 분류는 기존 코드로 유지한다. 아래 표는 현재 코드 기준이다.

### 접수 후 생성 실패

상태 조회와 같은 요청의 실패 재전송에 같은 문구를 제공한다. 게스트는 체험이 소진됐으므로 로그인 후 생성을 안내한다.

| 생성 실패 코드 | 회원 `action` | 게스트 `action` |
| --- | --- | --- |
| `AI_PROVIDER_ERROR` | 생성을 완료하지 못했어요. 잠시 후 다시 생성해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `AI_PROVIDER_CONNECTION_ERROR` | 생성 서비스에 연결하지 못했어요. 잠시 후 다시 생성해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `AI_PROVIDER_SERVER_ERROR` | 생성 서비스에 문제가 생겼어요. 잠시 후 다시 생성해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `AI_PROVIDER_CONFIGURATION_ERROR` | 현재 생성 기능을 이용하기 어려워요. 나중에 다시 이용해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `AI_PROVIDER_REQUEST_REJECTED` | 현재 생성 기능을 이용하기 어려워요. 나중에 다시 이용해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `AI_PROVIDER_RATE_LIMITED` | 지금은 생성 요청이 제한되고 있어요. 잠시 후 다시 생성해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `AI_PROVIDER_TIMEOUT` | 생성 시간이 초과됐어요. 잠시 후 다시 생성해 주세요. | 체험 생성 시간이 초과됐어요. 로그인 후 다시 생성해 주세요. |
| `AI_CONTENT_BLOCKED` | 작성한 내용으로 생성할 수 없어요. 내용을 바꿔 다시 시도해 주세요. | 작성한 내용으로 생성할 수 없어요. 내용을 바꾼 뒤 로그인해서 다시 생성해 주세요. |
| `AI_OUTPUT_TRUNCATED` | 생성 결과를 끝까지 완성하지 못했어요. 잠시 후 다시 생성해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `AI_RESPONSE_PROCESSING_ERROR` | 생성을 완료하지 못했어요. 잠시 후 다시 생성해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `GENERATION_INTERNAL_ERROR` | 생성을 완료하지 못했어요. 잠시 후 다시 생성해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `GENERATION_INTERRUPTED` | 생성이 도중에 중단됐어요. 잠시 후 다시 생성해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |
| `GENERATION_PENDING_TIMEOUT` | 대기 시간이 지나 생성을 시작하지 못했어요. 잠시 후 다시 생성해 주세요. | 대기 시간이 지나 체험 생성을 시작하지 못했어요. 로그인 후 다시 생성해 주세요. |
| `IMAGE_STORAGE_ERROR` | 이미지를 저장하거나 불러오지 못했어요. 잠시 후 다시 시도해 주세요. | 체험 생성에 실패했어요. 로그인 후 다시 생성해 주세요. |

`GENERATION_INTERNAL_ERROR`는 상태 조회의 `errorCode`다. 오류 응답의 `code`는 기존 매핑에 따라 `INTERNAL_SERVER_ERROR`이며, 생성 실패로 반환할 때 위 문구를 제공한다.

### 접수와 조회 관련 오류

접수 전 용량 초과는 체험을 사용하지 않으므로 게스트도 재시도할 수 있다.

| 오류 코드 | 사용자 행동 | 실제 `action` 문구 |
| --- | --- | --- |
| `GENERATION_CAPACITY_EXCEEDED` | 회원과 게스트 모두 잠시 후 재시도 | 현재 요청이 많아요. 잠시 후 다시 시도해 주세요. |
| `GENERATION_UNAVAILABLE` | 나중에 생성 기능 다시 이용 | 현재 생성 기능을 이용하기 어려워요. 나중에 다시 이용해 주세요. |
| `DAILY_GENERATION_LIMIT_EXCEEDED` | 회원이 내일 다시 생성 | 오늘 만들 수 있는 횟수를 모두 사용했어요. 내일 다시 생성해 주세요. |
| `GENERATION_IN_PROGRESS` | 새 요청 없이 현재 생성 완료 대기 | 이미 생성 중이에요. 새로 요청하지 말고 현재 생성이 끝날 때까지 기다려 주세요. |
| `IDEMPOTENCY_KEY_CONFLICT` | 기존 결과 확인 후 새로 작성 | 이전 요청과 내용이 달라요. 기존 요청의 결과를 확인한 뒤 새로 작성해 주세요. |
| `INVALID_IDEMPOTENCY_KEY` | 작성 내용 보관 후 생성 화면 다시 열기 | 요청 정보를 확인하지 못했어요. 작성한 내용을 보관한 뒤 생성 화면을 다시 열어 주세요. |
| `GENERATION_NOT_FOUND` | 이전 화면으로 돌아가 결과 확인 | 생성 기록을 찾을 수 없어요. 이전 화면으로 돌아가 생성 결과를 확인해 주세요. |
| `GENERATION_FAILED` | 성공한 일기 선택 후 다시 공유 | 완성된 그림일기가 없어요. 생성에 성공한 일기를 선택한 뒤 다시 공유해 주세요. |
| `GUEST_SESSION_REQUIRED` | 게스트가 체험 화면에 다시 진입 | 체험 정보를 확인할 수 없어요. 체험 화면에 다시 들어가 주세요. |
| `GUEST_SESSION_EXPIRED` | 게스트가 체험 화면에 다시 진입 | 체험 정보가 만료됐어요. 체험 화면에 다시 들어가 주세요. |
| `GUEST_TRIAL_ALREADY_USED` | 게스트가 로그인 후 새로 생성 | 무료 체험을 이미 사용했어요. 로그인 후 다시 생성해 주세요. |

## 타임아웃과 용량 초과 안내

- 접수 후 타임아웃으로 실패한 게스트 체험은 복구하지 않는다. 대기 시간 초과인 `GENERATION_PENDING_TIMEOUT`도 같은 기준을 적용하고, “로그인 후 다시 생성해 주세요.”를 안내한다. 회원의 기존 생성 횟수 복구 정책은 유지한다.
- `GENERATION_CAPACITY_EXCEEDED`는 접수 전 거절이므로 회원 생성 횟수와 게스트 체험을 차감하지 않는다. 회원과 게스트 모두 `action`으로 “현재 요청이 많아요. 잠시 후 다시 시도해 주세요.”를 안내한다.
- 체험을 사용한 뒤 실패한 경우와 접수 자체가 거절된 경우를 구분해, 실제로 가능한 다음 행동을 안내한다.

## 입력 차단 사유 보완

- Vertex AI의 `promptFeedback.blockReason`에 `OTHER` 또는 `JAILBREAK`가 오면 기존 `AI_CONTENT_BLOCKED`로 분류한다. 공식 응답에 정의된 차단 사유이므로 실제 운영 발생 기록이 없어도 처리한다.
- `finishReason=OTHER`는 생성이 끝난 이유를 구체적으로 모른다는 뜻이므로, 이 값만으로 콘텐츠 차단으로 분류하지 않는다.
- 입력 차단을 일반 응답 처리 오류로 잘못 분류해 재시도를 안내하거나 대체 AI로 요청하는 일을 막는다.
- 근거: [Vertex AI 응답 정의](https://cloud.google.com/vertex-ai/generative-ai/docs/reference/rest/v1/GenerateContentResponse#BlockedReason), [사용 중인 SDK 1.65.0의 차단 사유](https://github.com/googleapis/java-genai/blob/v1.65.0/src/main/java/com/google/genai/types/BlockedReason.java).

## 후속 작업

- 프론트가 `action`을 표시하고, 문구가 없거나 잘못된 형식이면 기존 일반 안내를 표시하도록 맞춘다.
- 프론트가 새 오류 코드를 받아도 실패 상태를 인식하고 조회를 종료하도록 맞춘다.
- #434의 설명을 이 결정에 맞춘다.
