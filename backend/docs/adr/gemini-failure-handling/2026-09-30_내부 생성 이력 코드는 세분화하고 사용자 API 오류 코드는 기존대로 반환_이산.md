# 2026-09-30 내부 생성 이력 코드는 세분화하고 사용자 API 오류 코드는 기존대로 반환

- 상태: 채택
- 작성일: 2026-09-30
- 작성자: 이산
- 결정 대상: 내부 생성 이력 코드와 사용자 API 오류 코드의 분리

## 배경

현재 생성 이력에는 서로 다른 실패 원인이 `AI_PROVIDER_ERROR`로 뭉쳐 기록될 수 있다. 원인 분석과 복구 정책 결정을 위해 내부 기록은 더 구체적이어야 한다. 반면 사용자에게 반환하는 API 오류 코드는 세부 원인을 모두 드러낼 필요가 없다.

## 결정

생성 이력에 저장하는 `GenerationErrorCode`는 다음 기준으로 구분한다.

| 내부 생성 이력 코드 | 분류 기준 | 사용자 API `ErrorType` |
| --- | --- | --- |
| `AI_PROVIDER_RATE_LIMITED` | Gemini가 HTTP 429를 반환 | `AI_PROVIDER_ERROR` |
| `AI_OUTPUT_TRUNCATED` | 스토리보드 응답 종료 사유가 `MAX_TOKENS` | `AI_PROVIDER_ERROR` |
| `AI_RESPONSE_PROCESSING_ERROR` | Gemini 응답의 JSON 파싱 또는 응답 검증 실패 | `AI_PROVIDER_ERROR` |
| `AI_PROVIDER_ERROR` | 그 밖의 AI 제공자 오류 또는 원인 미분류 | `AI_PROVIDER_ERROR` |
| `GENERATION_INTERNAL_ERROR` | 요청 준비 중 내부 오류 또는 예상하지 못한 애플리케이션 런타임 오류 | `INTERNAL_SERVER_ERROR` |

사용자 API 응답에 사용하는 `ErrorType`은 현재 계약을 유지한다. 내부 코드를 세분화해도 새로운 사용자 API 오류 코드는 추가하지 않는다. 기존 `AI_PROVIDER_TIMEOUT`, `IMAGE_STORAGE_ERROR`, `GENERATION_INTERRUPTED`의 API 코드도 유지한다.

## 이유

- 내부 실패 원인을 구분해 집계하고, 원인별 복구·운영 대응을 결정할 수 있다.
- 사용자 API 코드는 기존대로 유지해 프론트엔드 계약을 바꾸지 않고 내부 진단 정보도 불필요하게 노출하지 않는다.

## 결과

- `GenerationErrorCode`는 내부 생성 이력의 분류이고, `ErrorType`은 사용자 API 응답의 분류다. 두 코드는 같은 목적의 목록이 아니다.
- 내부 코드에서 API 코드로 변환하는 매핑을 테스트한다.
