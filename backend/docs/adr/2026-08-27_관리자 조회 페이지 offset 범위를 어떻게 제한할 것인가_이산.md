# 2026-08-27 관리자 조회 페이지 offset 범위를 어떻게 제한할 것인가

- 상태: 채택
- 작성자: 이산
- 결정 대상: 관리자 사용자·생성 이력 조회의 페이지 파라미터 검증

## 배경

관리자 조회 API는 `page`와 `size`로 Spring Data JPA 페이징을 사용한다. JPA의 `setFirstResult`는 정수 offset을 받기 때문에
`page * size`가 `Integer.MAX_VALUE`를 초과하면 조회 전에 서버 오류가 발생할 수 있다.

## 결정

- `size`는 기존처럼 `1 이상 100 이하`로 제한한다.
- `page`는 `Integer.MAX_VALUE / 100` 이하로 제한한다.
- 범위를 벗어난 요청은 `400 VALIDATION_ERROR`로 처리한다.

`size`의 최대값을 기준으로 `page`의 공통 상한을 정하면 모든 허용 조합에서 `page * size`가 정수 offset 범위를 넘지 않는다.

## 결과

- 사용자 조회와 생성 이력 조회가 같은 페이지 범위 정책을 사용한다.
- 비정상적으로 큰 페이지 요청이 `500 INTERNAL_SERVER_ERROR`로 처리되지 않는다.
- 실제 데이터가 없는 매우 큰 페이지를 허용해 불필요한 DB offset 비용이 커지는 문제는 별도의 페이지 정책으로 재검토한다.

## 재검토 조건

- 관리자 API의 페이지 크기 상한을 변경하는 경우
- offset 기반 페이징 성능이 문제가 되어 cursor 기반 페이징을 도입하는 경우
