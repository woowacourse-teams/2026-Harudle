# 2026-08-27 관리자 조회 결과를 어떤 패키지에 둘 것인가

- 작성일: 2026-08-27
- 작성자: 이산
- 결정 대상: 관리자 조회 계층의 패키지 책임

## 결정

관리자 모듈의 repository 인터페이스와 조회 결과 모델을 분리한다.

- `admin/repository`: repository 인터페이스와 조회 포트
- `admin/query`: 검색·상세 조회 결과, projection, 페이지 모델
- `admin/presentation/dto`: HTTP 요청·응답 DTO
- `admin/infrastructure`: JPA 기반 repository 구현

## 이유

`repository` 패키지에 인터페이스와 여러 조회용 record가 섞이면 저장소 접근 책임과 조회 결과 표현이 구분되지 않는다. 조회 record를 `query`에 두면 API DTO나 도메인 모델과도 명확히 분리할 수 있다.

## 결과

새로운 관리자 조회 API의 내부 결과 모델은 `admin/query`에 추가한다. 외부 응답 형식은 `admin/presentation/dto`에서 관리한다.

## 재검토 조건

- 관리자 조회 기능이 별도 read model 또는 CQRS 구조로 확장되는 경우
- 관리자 모듈 외에도 동일한 조회 계층 패키지 규칙을 적용해야 하는 경우
