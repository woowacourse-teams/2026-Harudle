# 피드 이미지 URL 발급 실패를 사진 단위로 처리한다

## 배경

목록의 사진 한 장에서 주소를 발급하지 못하면 피드 조회 전체가 503으로 끝날 수 있었다. 이 경우 정상 사진과 게시물도 화면에 나오지 않는다.

## 고려한 방법

- 오류를 피드 전체에 전달하면 호출자는 실패를 한 번에 알 수 있지만, 실패한 사진과 관계없는 게시물까지 볼 수 없다.
- 자동 재요청이나 별도 복구 API를 추가하면 사진을 다시 준비할 기회를 줄 수 있지만, 호출과 실패 처리 방식이 늘어난다. 이전 설계에서 이 작업 범위에 넣지 않기로 했다.
- 주소를 발급하지 못한 사진에만 빈 주소를 보내면 기존 이미지 안내를 재사용할 수 있다. 프런트가 빈 주소를 허용해야 한다.

## 결정과 이유

피드 목록과 상세에서 이미지 주소 발급 실패 또는 저장소 조회 예산 소진을 해당 사진의 결과로 처리한다. 나머지 사진과 게시물은 표시할 수 있어야 한다. 주소를 발급하지 못한 항목의 `imageUrl`과 `imageUrlExpiresAt`을 모두 `null`로 반환한다. 프런트는 해당 사진 자리에 “현재 이미지를 불러올 수 없습니다”를 표시한다.

피드 조회에서는 DB에 저장된 이미지 키의 검증 실패(`REQUEST_VALIDATION_ERROR`)도 해당 사진에만 적용한다.
잘못된 키의 주소는 발급하지 않으며 다른 저장소로 우회하지 않는다. 피드 자체의 권한 검사와 피드 게시 응답의 오류 처리는 그대로 유지한다.

응답에 주소를 넣지 못한 사진은 요청 추적 ID와 함께 `event=feed_image_url_unavailable`에 실패 종류별로
피드 ID를 모아 기록한다. 키 검증 실패는 데이터나 환경 설정을 확인할 수 있도록 ERROR로, 그 외 실패는 WARN으로 기록한다.
이 로그에는 이미지 키, 서명 URL, 자격 증명과 예외 원문을 넣지 않는다.

## 실제 동작과 결과

피드 조회는 주소를 받지 못한 사진이 있어도 그 게시물과 정상 사진을 반환한다. 피드 게시 응답은 기존 발급 경로를 사용한다. 로컬에서 이미지 실패가 있는 목록과 상세가 HTTP 200으로 응답하고, 같은 목록에서 정상 사진과 주소 없는 사진의 안내가 함께 표시되는 것을 확인했다.
