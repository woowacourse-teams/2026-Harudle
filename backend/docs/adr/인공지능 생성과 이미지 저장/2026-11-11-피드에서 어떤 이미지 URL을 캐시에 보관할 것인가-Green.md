# 피드에서 어떤 이미지 URL을 캐시에 보관할 것인가

## 배경

피드 목록과 상세를 조회할 때 같은 사진의 S3 서명 URL을 반복해서 만든다.
[이미지 URL 발급과 저장소 선택](<2026-10-06-이미지 URL 발급과 저장소 선택-작성자 미기재.md>)은
R2가 설정된 경우 응답마다 첫 이미지의 S3 존재 여부를 확인하고, 그 결과를 같은 응답의 다른 사진에
적용한다. 서명 비용을 줄이면서 이 저장소 선택과 피드 접근 권한 검사를 유지할 방법이 필요했다.

## 고려한 방법

- 매번 서명하면 발급 결과를 보관할 필요가 없지만, 자주 조회되는 사진도 반복해서 서명한다.
- S3와 R2의 주소 및 선택 결과를 함께 보관하면 줄일 수 있는 호출이 많지만, 저장소 복구나 장애가 발생한 뒤에도 캐시의 선택이 남을 수 있다.
- S3 서명 URL만 서버 안에서 보관하면 반복 서명을 줄이면서 매 응답의 저장소 선택을 유지할 수 있다. 서버를 재시작하면 캐시는 비워진다.

## 결정과 이유

피드 목록과 상세에만 백엔드 프로세스별 Caffeine 캐시를 사용한다. 같은 환경과 버킷 안에서 이미지 키를 기준으로 S3 서명 URL을 보관한다. 기본 용량은 최대 500개다. 매 응답의 S3 존재 확인과 R2 대체 경로를 유지해 저장소 상태 변화가 다음 조회에 반영되도록 한다. R2 URL은 필요할 때 발급한다.

## 실제 동작과 결과

기능은 `S3_URL_CACHE_ENABLED`로 켜고 끄며 기본값은 `false`다. 같은 서버의 유효한 캐시 적중은 새 서명을 피한다. 피드 접근 권한과 피드 데이터 조회는 요청마다 수행한다. 로컬 테스트에서 용량 상한, S3 저장소 선택, R2 주소 비캐싱, 캐시를 끈 경로를 확인했다. 운영에서의 적중률과 메모리 사용량은 이번 로컬 결과로 판단할 수 없다.
