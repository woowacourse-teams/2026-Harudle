# 공유 링크 생성 의존성 분리

공유 링크를 생성하려면 다음과 같은 다른 도메인의 정보가 필요하다.

- 그림일기가 존재하며 삭제되지 않았는지 확인한다.
- 그림일기가 현재 로그인한 사용자의 것인지 확인한다.
- 그림일기에 연결된 `ComicGeneration`을 조회한다.
- 생성 상태가 `SUCCEEDED`, `PROCESSING`, `FAILED` 중 무엇인지 확인한다.

공유 기능에서 `DiaryRepository`와 `ComicGenerationRepository`를 직접 사용하면 다른 도메인의 구현과 패키지 구조에 강하게 의존하게 된다. 이로 인해 해당 Repository나 엔티티가 변경될 때 공유 링크 생성 로직도 함께 변경될 수 있다.

따라서 공유 링크 생성에 필요한 정보를 읽는 역할을 `ShareLinkCreationReader` 인터페이스로 분리한다.

```java
public interface ShareLinkCreationReader {

    ShareLinkCreationInfo read(UUID userId, UUID diaryId);
}
```

`ShareLinkCreationInfo`는 공유 링크 생성에 필요한 최소한의 정보만 제공한다.

```java
public record ShareLinkCreationInfo(
        UUID generationId,
        GenerationStatus generationStatus
) {
}
```

`ShareLinkCreationReader`는 현재 로그인한 사용자의 ID와 공유하려는 그림일기의 ID를 입력받는다.

```text
입력
├── userId: 현재 로그인한 사용자 ID
└── diaryId: 공유하려는 그림일기 ID
```

입력받은 값을 사용하여 내부에서 다음 내용을 확인한다.

- 그림일기가 존재하는지 확인한다.
- 그림일기가 삭제되지 않았는지 확인한다.
- 그림일기가 현재 로그인한 사용자의 것인지 확인한다.
- 그림일기에 연결된 `ComicGeneration`이 존재하는지 확인한다.

확인이 끝나면 공유 링크 생성에 필요한 `generationId`와 `generationStatus`만 `ShareLinkCreationInfo`로 반환한다. `userId`와 `diaryId`는 조회와 소유권 확인을 위한 입력값이므로 반환하지 않는다.

`ShareLinkCreationReader`는 생성 상태에 따른 비즈니스 판단을 수행하지 않는다. 생성 상태가 `SUCCEEDED`인지 확인하고, `PROCESSING` 또는 `FAILED`일 때 예외를 발생시키는 책임은 `ShareLinkService`가 가진다.

`ShareLinkService`는 다른 도메인의 Repository를 직접 사용하지 않고 `ShareLinkCreationReader`를 통해 필요한 정보를 받는다. 이후 생성 상태를 확인하고 `ShareLinkRepository`에서 기존 공유 링크를 조회하거나 새로운 공유 링크를 저장한다.

```text
ShareLinkService
├── ShareLinkCreationReader
│   ├── DiaryRepository
│   └── ComicGenerationRepository
└── ShareLinkRepository
    └── share_links
```

`ShareLinkCreationReader`의 실제 구현체는 일기 및 생성 기능이 병합된 후 해당 도메인의 Repository를 조합하여 구현한다. 구현체가 준비되기 전에는 테스트에서 Fake 또는 Mock을 사용한다.

`ShareLinkRepository`는 `ShareLinkCreationReader`와 별도로 유지한다. `ShareLinkCreationReader`는 다른 도메인에서 공유 링크 생성에 필요한 정보를 읽는 역할이고, `ShareLinkRepository`는 공유 링크 자체의 조회와 저장을 담당한다.

각 구성 요소의 책임은 다음과 같다.

```text
ShareLinkCreationReader
├── 그림일기 존재 여부 확인
├── 그림일기 삭제 여부 확인
├── 사용자 소유권 확인
└── 생성 결과 ID와 상태 제공

ShareLinkService
├── 생성 상태에 따른 비즈니스 판단
└── 기존 공유 링크 반환 또는 신규 생성

ShareLinkRepository
└── 공유 링크 조회 및 저장
```

공유 링크는 그림일기 원문이 아니라 성공한 생성 결과를 공유하므로 `share_links`는 `diary_id` 대신 `generation_id`를 참조한다. 따라서 기존 공유 링크는 `generationId`로 조회한다.

이 구조를 통해 다른 도메인의 구현 변경이 공유 링크 생성 로직에 직접 전파되는 범위를 줄이고, 다른 기능이 병합되기 전에도 공유 링크 서비스의 동작을 독립적으로 테스트할 수 있다.
