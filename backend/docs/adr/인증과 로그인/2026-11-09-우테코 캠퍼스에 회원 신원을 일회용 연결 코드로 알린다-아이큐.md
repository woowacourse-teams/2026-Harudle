# 우테코 캠퍼스에 회원 신원을 일회용 연결 코드로 알린다

## 결정 (Decision)

우리는 우테코 캠퍼스(`campus.harudle.com`)에 하루들 회원 신원을 알릴 때, 로그인한 회원에게 60초짜리 일회용 연결 코드를 발급하고 캠퍼스 서버가 클라이언트 비밀값으로 그 코드를 교환하게 한다.

- 발급: `POST /api/v1/campus/link-codes` (Bearer, 약관 동의 · 정지 여부 · 닉네임 확인). 코드와 state는 SHA-256 해시만 `campus_link_codes`에 저장한다.
- 교환: `POST /api/v1/campus/link-codes/exchange` (`Authorization: Basic base64(campus:비밀값)`). 한 번의 `UPDATE … RETURNING`으로 사용 처리해 같은 코드를 두 번 교환할 수 없다.
- 캠퍼스에 주는 정보는 회원 ID · 닉네임 · 프로필 사진뿐이다. 이메일 · 실명 · 토큰은 주지 않는다.
- 돌아갈 주소(`harudle.campus.redirect-uri`)와 비밀값 해시(`harudle.campus.client-secret-sha256`)는 서버 설정으로만 정한다.

## 근거 (Rationale)

- Refresh Token 쿠키는 `www.harudle.com` 전용이고, Access Token은 HS256 공유 비밀키로 서명한다. 캠퍼스가 이 토큰을 쓰려면 쿠키 범위를 넓히거나 서명 키를 나눠야 하며, 캠퍼스가 일기 조회·삭제까지 가능한 전체 권한을 갖게 된다.
- 캠퍼스는 회원이 누구인지만 알면 된다. OAuth 인가 코드와 같은 방식(짧은 수명 · 일회용 · 서버 간 교환 · state 결합)이 필요한 만큼만 알린다.
- 대안: 캠퍼스 출처에 CORS를 열고 브라우저가 하루들 API를 직접 호출 → 토큰이 캠퍼스 페이지에 노출되고 Refresh Token 교체가 본 사이트와 충돌해 기각했다.
- 대안: 하루들을 표준 OAuth 제공자로 만들기 → 클라이언트가 캠퍼스 하나뿐이라 범위에 비해 크다. 클라이언트가 늘면 다시 검토한다.

## 상태 (Status)

- 제안됨 (Proposed)

## 결과 (Consequences)

- 하루들은 캠퍼스에 의존하지 않는다. 캠퍼스가 꺼져도 하루들 기능에는 영향이 없다(단방향).
- 캠퍼스는 회원 탈퇴를 알 수 없다. 캠퍼스는 마지막 로그인 후 90일이 지난 사용자 정보를 지운다.
- 개인정보처리방침에 "우테코 캠퍼스 로그인 연동"(회원 ID · 닉네임 · 프로필 사진)을 처리 목적으로 추가해야 한다.
- 비밀값 원본은 캠퍼스 서버에만 있고, 하루들에는 해시만 둔다. 비밀값을 바꿀 때는 하루들 해시를 먼저 바꾸고 캠퍼스 값을 바꾼다.
- 교환 API에는 요청 제한이 없다. 코드가 32바이트 무작위 값이고 60초 · 일회용이며 비밀값이 필요해 추측 공격 위험은 낮다고 본다.
