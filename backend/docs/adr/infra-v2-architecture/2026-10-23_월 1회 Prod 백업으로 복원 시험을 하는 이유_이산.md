# 2026-10-23 월 1회 Prod 백업으로 복원 시험을 하는 이유

- 작성일: 2026-10-23
- 작성자: 이산
- 상태: 채택, 서버 적용 및 복원 시험 전
- 결정 대상: pgBackRest 백업과 WAL을 이용한 정기 복원 시험

## 배경

백업 명령이 성공해도 실제 데이터를 복구할 수 있는지는 복원해 봐야 알 수 있다.
Prod의 데이터 유실 최대 5분과 서비스 복구 4시간 목표도 아직 시험으로 확인하지 않았다.
추가 EC2를 두지 않는 조건 안에서 복원 시험을 반복한다.

## 결정 요인

- 실제 S3 백업과 WAL로 지정한 시점의 데이터를 복구할 수 있는지 확인한다.
- Prod DB를 중단하거나 기존 Dev 데이터를 덮어쓰지 않는다.
- 시험에 사용한 Prod 데이터가 Dev 앱이나 외부에 노출되지 않게 한다.
- 실제 소요 시간과 실패 원인을 기록한다.

## 고려한 대안

### 대안 1: 장애가 생겼을 때 처음 복원

장점은 평소 시험 작업과 자원 사용이 없다는 점이다.
단점은 복원 실패나 절차 누락을 실제 장애 때 처음 발견한다는 점이다.

### 대안 2: 월 1회 분리된 임시 컨테이너에서 복원

장점은 Prod를 중단하지 않고 복원 절차를 반복해서 확인할 수 있다는 점이다.
단점은 Dev DB EC2의 메모리, CPU와 디스크를 함께 사용하고 시험 데이터를 관리해야 한다는 점이다.

## 결정

대안 2를 채택한다.

| 항목 | 결정 |
| --- | --- |
| 주기 | 월 1회 실시한다. 백업 설정을 바꾼 뒤에도 추가로 실시한다. |
| 장소 | Dev DB EC2의 분리된 임시 PostgreSQL 컨테이너를 사용한다. |
| 복원 자료 | Prod의 S3 물리 백업과 필요한 WAL을 사용한다. |
| 확인 내용 | 지정한 시점으로 복원하고 주요 데이터를 조회한다. |
| 기록 | 목표 복구 시점, 사용한 백업, 실제 복구한 데이터 시각, 단계별 소요 시간과 실패 원인을 남긴다. |
| 시험 종료 | 임시 컨테이너와 복원 데이터, 임시 접속 정보를 삭제한다. |

기존 Dev DB와 다른 데이터 볼륨과 네트워크를 사용한다.
Dev 앱을 시험 DB에 연결하지 않고, DB 포트를 외부에 공개하지 않는다.
시험 환경에서 Prod DB에 접속하거나 S3 원본 백업을 변경하지 않는다.

복원 시간은 Prod 복구 목표 4시간과 비교한다.
다만 이미 준비된 Dev 서버에서 DB를 복원한 시간만으로 4시간 목표를 달성했다고 판단하지 않는다.
전체 복구 목표에는 장애 발견, 담당자 대응, 서버 준비와 주요 앱 기능 확인도 포함된다.

## 긍정적 결과

- 백업 파일과 필요한 WAL을 실제로 사용할 수 있는지 반복해서 확인한다.
- 장애 전에 복원 절차의 누락과 권한 문제를 발견할 수 있다.
- 데이터가 늘어날 때 복원 시간이 어떻게 달라지는지 확인할 수 있다.

## 부정적 결과와 트레이드오프

- 시험 중 Dev의 성능이 떨어지거나 디스크 사용량이 늘 수 있다.
- Prod 데이터를 임시로 보관하므로 접근 차단과 삭제 확인이 필요하다.
- 월 1회 성공한 결과가 이후 모든 백업의 복구 가능성을 보장하지는 않는다.

## 후속 결정과 재검토 조건

- 월간 실행 날짜와 시간, 담당자와 구체적인 복원 명령을 정한다.
- 첫 실행 전에 Dev DB EC2의 메모리와 디스크 여유를 확인한다. 여유가 부족하면 동시 실행하지 않고 시험 시간과 자원 사용 방식을 다시 정한다.
- 지정한 시점 전후의 기록을 구분할 수 있도록 조회 대상과 기대 결과를 정한다.
- 첫 구축과 복원 절차 변경 시에는 서버 준비와 앱 확인까지 포함한 전체 복구 시험도 계획한다.
- 복원 실패나 4시간 목표 초과가 확인되면 원인을 수정하고 다시 시험한다.

## 구현과 검증

주기와 시험 방식을 결정했다. 복원 작업과 예약 실행은 아직 구현하지 않았다.
실제 시험에서 지정한 시점의 복구 결과와 주요 데이터 조회 결과를 기록한다.
시험 성공과 실패 모두 임시 데이터를 정리하고, 기존 Dev DB와 Prod 백업이 유지되는지 확인한다.
Prod 데이터가 포함된 조회 결과를 공개 로그나 Discord에 남기지 않는다.
