## 적용 범위

다음 PR의 구현 기준으로 작성했다. 상태의 `채택`은 해당 PR에서 구현한 결정을 뜻하며, 모든 피드 코드를 병합하거나 운영 배포했다는 뜻은 아니다.

PR #342·#343은 `develop-backend`에 병합됐으며, PR #344는 리뷰와 통합을 진행하는 범위다. 프론트 CSRF 요청 수정은 `fix/feed-like-csrf-request`의 로컬 커밋으로 준비했으며 아직 병합·배포한 상태가 아니다.

- [PR #342 피드 좋아요와 인앱 알림 기록](https://github.com/woowacourse-teams/2026-Harudle/pull/342)
- [PR #343 댓글 조회 작성 삭제](https://github.com/woowacourse-teams/2026-Harudle/pull/343)

피드 게시·삭제, 카테고리 관리, 닉네임 배정과 FCM 발송 자체는 이 묶음의 결정 대상이 아니다. 피드 삭제로 반응과 알림을 숨기는 상위 정책은 [2026-10-11 피드 삭제 ADR](https://github.com/woowacourse-teams/2026-Harudle/blob/0f1937cba320307ef7f1c8992e5f68f8a77f98c6/backend/docs/adr/feed-deletion-policy/2026-10-11_피드와%20연결%20데이터의%20삭제%20방식을%20어떻게%20정할%20것인가_캐모.md)을 따른다.

## 통합 상태와 남은 확인 사항

- 반응 포트는 `FeedInteractionService` 하나로 통합하고 native 카운터 어댑터를 제거했다. 피드·일기·피드 작성자가 활성 상태인지 같은 기준으로 확인하며, 실제 일기·피드 삭제 서비스와의 잠금 순서도 함께 검증한다.
- 공개 프로필 구현체를 연결할 때 댓글·알림 제공자가 같은 DB 트랜잭션에 참여하는지 확인해야 한다. DB에서 탈퇴가 확인된 댓글 작성자는 익명화하지만, 활성 작성자의 프로필 누락은 장애로 처리한다.
- 반응 변경의 Bearer와 CSRF 명세는 유지한다. 기존 쿠키 API 보호를 보존하고, 좋아요·댓글 변경과 알림 읽음 PATCH의 Scalar 요구를 실제 체인과 맞춘다. 프론트 수정 병합과 실제 화면 연동 검증은 별도로 진행한다.
- 공통 회원 자격 조회 포트와 프로필 유효성 검증의 제공자 책임은 각 담당 영역의 계약을 통합할 때 정리한다.
- 기존 소프트 삭제 데이터와 알림 이력의 보관 기간 및 물리 정리 주기는 별도 결정으로 남긴다.
