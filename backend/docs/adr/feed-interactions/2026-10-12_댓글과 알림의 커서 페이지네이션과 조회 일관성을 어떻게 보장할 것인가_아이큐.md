# 2026-10-12 댓글과 알림의 커서 페이지네이션과 조회 일관성을 어떻게 보장할 것인가

- 상태: 채택
- 작성일: 2026-10-12
- 수정일: 2026-10-13
- 작성자: 아이큐
- 결정 대상: 댓글·알림 정렬 경계, 커서 검증과 작성자 상태·프로필 및 알림 미읽음 수의 조회 일관성

## 배경

댓글과 알림은 조회 사이에도 추가·삭제될 수 있다. offset으로 페이지를 건너뛰면 앞쪽 데이터가 변경될 때 같은 항목이 다시 나오거나 일부 항목을 지나칠 수 있다. 작성 시각만으로 경계를 정해도 같은 시각의 행들을 구분할 수 없다.

알림 응답은 한 페이지의 항목과 전체 미읽음 수를 함께 반환한다. 두 쿼리가 다른 시점의 상태를 읽으면 화면의 항목과 미읽음 수가 한 번의 요청 안에서도 서로 맞지 않을 수 있다.

댓글은 작성자 탈퇴 여부를 확인한 뒤 활성 작성자의 프로필을 조회한다. 두 조회 사이에 탈퇴가 커밋되면 정상 탈퇴를 활성 프로필 누락으로 오인해 목록 전체를 503으로 처리할 수 있다.

## 결정 요인

- 같은 작성 시각에도 다음 페이지 경계를 결정할 수 있어야 한다.
- 경계 항목이 삭제되더라도 다음 페이지 조회에 그 행을 다시 찾을 필요가 없어야 한다.
- 다른 피드·계정·종류의 커서를 재사용하지 않아야 한다.
- 알림 한 응답의 목록과 미읽음 수는 같은 DB 스냅샷에서 조립해야 한다.
- 댓글 한 응답의 작성자 상태와 프로필도 같은 DB 스냅샷에서 읽어야 한다.

## 고려한 대안

### 대안 1 offset 페이지네이션

페이지 번호 접근이 쉽고 구현이 단순하다. 반면 계속 변경되는 댓글·알림 목록에서 앞쪽 행 수에 영향을 받는다. 현재 무한 스크롤 API에는 채택하지 않는다.

### 대안 2 작성 시각 하나로 커서 구성

정렬 기준이 단순하지만 같은 시각의 데이터가 여러 개면 경계가 모호하다. UUID를 보조 정렬 기준으로 함께 사용한다.

### 대안 3 작성 시각과 UUID를 함께 저장한 커서

복합 경계로 같은 시각의 행을 구분하며, 삭제된 경계 행을 다시 조회하지 않아도 된다. 범위와 형식 검증이 추가되지만 현재 목록 계약에 채택한다.

## 결정

### 정렬과 경계

댓글은 `created_at ASC, id ASC`, 알림은 `created_at DESC, id DESC`로 조회한다. 댓글의 다음 경계는 더 큰 시각·UUID, 알림의 다음 경계는 더 작은 시각·UUID다. UUID 순서는 같은 시각의 결정적 정렬을 위한 것이며 실제 작성 순서를 나타내는 순번이 아니다.

기본 페이지 크기는 20, 허용 범위는 1~50이다. `size + 1`개를 조회해 `hasNext`를 확인하고, 실제 반환한 마지막 항목의 DB 시각과 ID로 다음 커서를 만든다. 마지막 페이지는 `nextCursor=null`이다.

커서가 담고 있는 정렬 값으로 다음 범위를 조회하므로 경계 댓글이나 알림이 사라져도 경계 행의 존재를 요구하지 않는다.

### 커서 검증

`CommentCursorCodec`과 `NotificationCursorCodec`는 버전·종류·범위 ID·작성 시각·항목 ID를 URL-safe Base64로 인코딩한다. 범위 ID는 댓글에서는 피드 ID, 알림에서는 현재 수신자 ID다.

길이·Base64 형식·버전·종류·UUID 형식·범위 ID를 검증하고, PostgreSQL TIMESTAMPTZ에 바인딩할 시각은 연도 1~9999와 마이크로초 정밀도로 제한한다. 잘못된 커서는 `400 INVALID_CURSOR`로 처리한다.

Base64는 서명이나 암호화가 아니다. 커서의 형식과 범위를 검증해도 사용자가 같은 범위의 경계 값을 바꿀 수 있다. 접근 권한은 인증 정보와 SQL의 피드·수신자 조건으로 보장하며, 커서를 권한 증명으로 사용하지 않는다.

### 댓글과 알림 조회 스냅샷

알림 목록 서비스는 읽기 전용 `REPEATABLE_READ` 트랜잭션에서 목록·전체 미읽음 수를 읽는다. DB 프로필 제공자가 같은 트랜잭션에 참여하면 프로필도 같은 스냅샷을 읽는다. 외부 저장소나 별도 트랜잭션의 제공자까지 자동으로 보장하지 않는다.

`unreadCount`는 커서와 페이지 크기에 제한되지 않는 전체 노출 가능한 미읽음 수다. 예를 들어 미읽음 알림이 25개이고 size가 20이면 항목 20개와 `unreadCount=25`를 반환한다.

댓글 목록도 읽기 전용 `REPEATABLE_READ`를 사용한다. 같은 스냅샷에서 댓글 작성자의 `deleted_at`과 활성 작성자 프로필을 읽어 조회 도중 탈퇴를 장애로 오인하지 않는다. 이 보장은 프로필 제공자가 같은 DB·같은 트랜잭션에 참여할 때 적용된다.

탈퇴 작성자의 댓글을 제거하지 않고 작성자만 익명화하므로 페이지 크기·정렬·커서 경계를 유지한다. 탈퇴 댓글이 페이지의 마지막 항목이어도 그 댓글의 작성 시각과 ID를 다음 커서로 사용한다. 조회는 댓글 수를 변경하지 않는다.

## 긍정적 결과

- 같은 시각의 항목과 삭제된 경계에서도 다음 범위를 결정할 수 있다.
- 알림 한 응답의 목록과 전체 미읽음 수가 DB의 같은 상태를 기준으로 한다.
- 댓글의 작성자 상태와 프로필을 한 시점으로 읽고 정상 탈퇴와 프로필 장애를 구분한다.
- 종류와 범위가 다른 커서의 실수성 재사용을 명시적으로 거부한다.

## 부정적 결과와 트레이드오프

- 페이지 번호로 임의 위치에 바로 이동하는 용도에는 적합하지 않다.
- 한 요청의 스냅샷이지 모든 페이지를 처음 조회한 상태로 고정하는 기능은 아니다. 페이지 사이에 새 알림·취소·삭제·읽음이 반영돼 목록과 미읽음 수가 달라질 수 있다.
- 조회 도중 삭제가 커밋돼도 이미 시작한 스냅샷은 삭제 전 알림을 보여줄 수 있다. 후속 상세·읽음 요청의 404를 처리해야 한다.
- REPEATABLE READ 트랜잭션이 길어지지 않도록 같은 트랜잭션 안의 프로필 조회와 외부 호출 비용을 관리해야 한다.

## 후속 결정과 재검토 조건

정렬 키를 수정할 수 있는 기능, 여러 페이지의 고정 스냅샷, 커서 변조 자체를 막는 서명이나 임의 페이지 접근이 필요해지면 커서 계약을 다시 검토한다. 미읽음 수 조회가 병목이 되면 캐시·집계를 검토하되 현재 가시성 조건과 일관성 보장 수준도 함께 정한다.
