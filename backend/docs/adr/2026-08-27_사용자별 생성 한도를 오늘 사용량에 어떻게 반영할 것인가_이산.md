# 사용자별 생성 한도를 오늘 사용량에 어떻게 반영할 것인가

- 상태: 채택
- 작성자: 이산

## 결정

- `users.daily_generation_limit`을 사용자별 지속 한도로 사용한다.
- 오늘 사용량 행이 처음 생성될 때 사용자별 한도를 `daily_generation_usage.limit_count`에 스냅샷한다.
- 오늘 사용량 최초 생성과 사용자별 한도 변경은 동일한 사용자 행에 `FOR UPDATE` 잠금을 적용해 직렬화한다.
- 오늘 사용량 행이 있으면 한도 변경 시 `max(새 한도, used_count)`로 오늘 스냅샷만 갱신한다.
- 오늘 사용량을 초기화하면 `used_count`가 0이 되므로 현재 사용자 한도로 오늘 스냅샷을 다시 갱신한다.
- 오늘 사용량 행이 없으면 행을 만들지 않고, 다음 최초 차감 요청부터 변경된 한도를 사용한다.
- 오늘 사용량 조회에서 행이 없으면 사용자의 현재 한도를 사용해 빈 사용량을 반환한다.

## 이유

사용자별 한도 변경을 실제 생성 차감과 일관되게 적용하면서도, 이미 사용한 횟수보다 한도가 작아져 데이터베이스 제약 조건을 위반하는 상황을 막기 위해서다.
사용량 행이 없는 상태에서 최초 생성과 한도 변경이 동시에 실행되면 한도 변경이 0건 갱신으로 끝나거나 최초 요청의 이전 한도가 스냅샷될 수 있으므로,
두 경로가 같은 사용자 행 잠금을 먼저 획득하도록 한다.

## 결과

같은 날짜의 사용량은 당시 적용된 한도를 보존하되, 사용량을 초기화한 시점에는 현재 사용자 한도를 다시 반영한다.
한도 변경은 오늘에만 반영되고 과거 사용량은 변경하지 않는다.
최초 사용량 생성과 한도 변경이 동시에 실행되어도 사용자 한도와 오늘 사용량 스냅샷이 서로 다른 값으로 남지 않는다.
