# 2026-08-27 관리자 생성 사용량과 한도 API를 어떻게 구성할 것인가

- 작성일: 2026-08-27
- 작성자: 이산
- 결정 대상: 관리자 대시보드의 생성 사용량 조정과 사용자별 생성 한도

## 배경

관리자는 사용자의 오늘 생성 사용량을 복구하거나 전체 초기화할 수 있어야 하고, 사용자별 일일 생성 한도도 변경할 수
있어야 한다. 사용량을 임의의 값으로 직접 지정하는 API를 추가할지 결정이 필요하다.

## 결정

사용량 직접 지정 API는 제공하지 않는다.

- `restore`: 오늘 사용량을 지정한 횟수만큼 줄인다.
- `reset`: 오늘 사용량을 0으로 초기화한다.
- `generation-limit`: 사용자의 일일 생성 한도를 변경한다.

사용자별 일일 생성 한도는 `users.daily_generation_limit`에 저장한다. `daily_generation_usage.limit_count`는 해당 날짜에
적용된 한도의 스냅샷으로 저장한다. 따라서 사용자별 한도를 변경해도 과거 날짜의 사용량 기록은 바뀌지 않는다.

오늘 사용량 기록이 이미 있으면 새 한도를 반영하되, 새 한도가 이미 사용한 횟수보다 작을 때는 사용량을 변경하지 않고
오늘 스냅샷 한도를 `usedCount` 이상으로 유지한다. 오늘 기록이 없으면 사용량 행을 만들지 않고 사용자별 한도만 변경한다.

## 결과

- 사용량 변경 의도가 `restore`와 `reset`으로 명확해진다.
- 직접 덮어쓰기로 인해 복구·초기화 규칙이 우회되는 문제를 막는다.
- 사용자별 정책과 날짜별 실제 적용 한도를 분리해 과거 기록을 보존한다.

## 재검토 조건

- 관리자가 사용량을 임의의 값으로 직접 지정해야 하는 운영 요구가 생기는 경우
- 생성 한도를 다음 날짜부터 적용해야 하는 정책으로 변경하는 경우
