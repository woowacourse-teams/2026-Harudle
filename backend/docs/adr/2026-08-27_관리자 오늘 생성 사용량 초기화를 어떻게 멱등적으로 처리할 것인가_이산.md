# 2026-08-27 관리자 오늘 생성 사용량 초기화를 어떻게 멱등적으로 처리할 것인가

- 작성일: 2026-08-27
- 작성자: 이산
- 결정 대상: 관리자의 오늘 생성 사용량 전체 초기화

## 문제

오늘 사용량이 새 한도보다 많은 상태에서 한도를 낮추면, `used_count <= limit_count` 제약을 지키기 위해 오늘
스냅샷의 한도는 기존 사용량까지 유지된다.

예를 들어 `used_count = 5`, 오늘 스냅샷 `limit_count = 5`인 사용자의 지속 한도를 `3`으로 낮추면, 오늘 스냅샷은
`max(3, 5) = 5`로 남는다. 이 상태에서 사용량을 `0`으로 초기화하면서 스냅샷 한도를 그대로 두면 최종 상태가
`used_count = 0`, `limit_count = 5`가 되어 사용자가 새 한도 `3`보다 많이 생성할 수 있다.

## 결정

`PUT /api/v1/admin/users/{userId}/generation-usage/reset`은 오늘 사용량 행이 있으면 `used_count`를 `0`으로 대입하고
사용자별 현재 한도를 `limit_count`에 반영한다. 행이 없으면 사용자별 현재 한도를 사용한 기본 사용량을 반환한다.

- 기존 사용량 행의 `limit_count` 스냅샷은 초기화 시점의 사용자별 현재 한도로 갱신한다.
- 사용량 행이 없어도 성공 처리하며 새 행은 만들지 않는다.
- 이미 `used_count = 0`인 행에 다시 요청해도 같은 결과를 반환한다.
- 대상 사용자가 없으면 `USER_NOT_FOUND`, 탈퇴 사용자면 `INACTIVE_USER`를 반환한다.

## 이유

초기화는 “현재 상태를 0으로 만든다”는 절대적 대입이므로 여러 번 실행해도 결과가 같아야 한다. `used_count`가 0이 되면
기존 사용량 때문에 높은 한도를 유지할 이유가 없으므로, 현재 사용자 한도를 다시 스냅샷한다. 행이 없는 사용량을
초기화하기 위해 빈 행을 생성하면 조회만으로 데이터가 생기고, 해당 날짜의 실제 사용 기록과 정책 스냅샷을 혼동할 수 있다.

## 결과

- 같은 초기화 요청을 재시도해도 사용량이 추가로 변하지 않는다.
- 사용량이 없는 사용자도 일관된 `usedCount=0` 응답을 받는다.
- 초기화만으로 `daily_generation_usage` 행이 생성되지 않는다.

## 재검토 조건

- 초기화 작업의 감사 로그나 변경 이력이 필요한 경우
- 초기화와 생성 요청의 동시 실행 결과를 별도로 보장해야 하는 경우
