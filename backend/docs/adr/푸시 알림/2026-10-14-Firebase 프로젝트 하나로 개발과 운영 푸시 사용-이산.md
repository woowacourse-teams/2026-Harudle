# 2026-10-14 Firebase 프로젝트 하나로 개발과 운영 푸시 사용

- 작성일: 2026-10-14
- 작성자: 이산
- 결정 대상: 개발·운영 환경의 Firebase 프로젝트 분리 여부

## 배경

하루들은 개발 DB와 운영 DB를 따로 쓴다. Firebase 프로젝트도 두 개 만들어야 개발 중 게시한 피드의 알림이 운영 사용자에게 가지 않는지 검토했다.

쉽게 말해 **DB는 알림을 받을 기기의 주소록**, **FCM은 그 주소로 알림을 배달하는 곳**이다. 같은 배달 서비스를 써도 개발 서버가 개발 DB의 주소록만 읽으면 운영 DB에 등록된 기기를 자동으로 수신 대상으로 삼지 않는다.

예를 들어 개발 DB에 철수의 휴대폰만 등록돼 있다면, 개발 피드의 알림은 철수의 휴대폰용으로 예약된다. 운영 DB에만 등록된 영희의 기기는 이 주소록에 없으므로 대상이 아니다.

## 결정

- 지금은 Firebase 프로젝트 하나를 개발·운영 환경에서 함께 쓴다.
- 개발 서버는 개발 DB의 푸시 등록만, 운영 서버는 운영 DB의 푸시 등록만 조회해 발송 작업을 만든다.
- 프론트엔드와 백엔드는 같은 Firebase 프로젝트 설정을 사용한다. 환경마다 연결할 DB는 계속 분리한다.

## 이유

현재 Firebase는 피드 푸시에만 사용한다. 프로젝트를 둘로 나누면 설정과 인증 정보를 각각 관리해야 하지만, 이미 분리된 DB 덕분에 개발 피드 게시가 곧바로 운영 사용자 전체에게 알림을 보내지는 않는다. FCM 자체는 무료이므로 프로젝트 수를 줄이는 이유는 요금보다 **설정 관리의 단순함**이다. [Firebase 요금 안내](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans)

두 프로젝트를 쓰면 개발·운영 발송 대상을 Firebase에서도 분리할 수 있다. 지금은 그 추가 경계보다 한 프로젝트로 시작하는 편을 선택한다. [Firebase의 환경별 프로젝트 안내](https://firebase.google.com/docs/projects/dev-workflows/overview-environments)

## 결과

- 운영 사용자라도 개발 사이트에서 푸시를 켜 개발 DB에 등록했다면 개발 알림을 받을 수 있다. 수신 여부는 사용자 이름이 아니라 **어느 DB의 주소록에 등록됐는지**로 결정된다.
- 개발·운영의 DB 연결이나 발송 대상 목록을 잘못 섞으면 운영 기기에 테스트 알림이 갈 수 있으므로, 각 서버가 올바른 DB를 쓰는지 배포 설정에서 확인한다.
- 나중에 Firebase 프로젝트를 분리하면 새 프로젝트에서 웹 푸시를 다시 등록하고 FID를 서버에 갱신해야 한다.
