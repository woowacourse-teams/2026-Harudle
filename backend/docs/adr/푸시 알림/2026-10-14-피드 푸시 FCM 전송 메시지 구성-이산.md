# 피드 푸시 FCM 전송 메시지 구성

- 작성일: 2026-10-14
- 작성자: 이산
- 결정 대상: 새 피드 알림을 FCM에 보낼 때 넣는 값

## 배경

피드가 게시되면 기기마다 발송 작업이 DB에 저장된다. FCM에 실제로 보낼 메시지에는 발송 대상과 알림 내용이 필요하다. 브라우저가 알림을 눌렀을 때 열 주소도 정해야 한다.

## 결정과 현재 구현

- 서버는 등록된 FID를 FCM 발송 대상으로 사용한다. 알림 제목은 `새 만화가 올라왔어요`, 본문은 `새 피드를 확인해 보세요.`다.
- 메시지의 `data`에는 `eventId`, `type=FEED_PUBLISHED`, `feedId`를 문자열로 넣는다. 다시 보내야 할 때도 같은 `eventId`를 사용한다.
- 웹 알림의 `tag`에는 `eventId`를 넣는다. 같은 알림이 화면에 남아 있으면 새 알림이 기존 알림을 교체할 수 있다. 이미 닫은 알림은 다시 나타날 수 있다.
- 웹 메시지의 TTL은 7일이다. FCM이 메시지를 수락했지만 기기가 연결되지 않았다면, FCM은 수락 시점부터 최대 7일 동안 전달을 시도한다.
- 피드 상세 주소가 HTTPS이면 알림 클릭 주소로 넣는다. 로컬 개발 주소처럼 HTTP이면 클릭 주소를 넣지 않는다. FCM 웹 클릭 주소에는 HTTPS가 필요하다.

FCM 사용 설정을 켠 서버에서만 전송 코드가 준비된다. 설정을 끈 서버는 Firebase 인증 정보 없이 시작할 수 있다.

## 확인한 내용과 다음 작업

테스트에서 FID, 제목과 본문, `data`의 세 필드, `tag`, 7일 TTL, HTTPS 클릭 주소를 확인했다. HTTP 로컬 주소에는 클릭 주소가 들어가지 않는 것도 확인했다.

현재는 **FCM으로 보낼 메시지를 만드는 코드까지** 작성했다. DB의 발송 작업을 가져와 이 코드를 호출하는 워커는 아직 연결하지 않았다. FCM의 성공 응답은 요청을 수락했다는 뜻이며, 기기에 알림이 도착했다는 뜻은 아니다.
