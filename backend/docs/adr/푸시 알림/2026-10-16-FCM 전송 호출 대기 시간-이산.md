# FCM 전송 호출 대기 시간

- 작성일: 2026-10-16
- 작성자: 이산
- 결정 대상: Firebase Admin SDK의 HTTP 전송 대기 시간

## 배경

워커는 FCM의 응답을 기다리는 동안 다음 발송 작업을 처리하지 못한다. 현재 작업 점유 시간은 5분이다. 응답이 오지 않아 점유 시간이 끝나면 다른 워커가 같은 작업을 다시 가져갈 수 있다.

## 결정

- Firebase Admin SDK의 연결 대기는 10초, 응답 읽기 대기는 30초, 요청 쓰기 대기는 10초로 설정한다.
- 타임아웃이 나면 전송 결과를 알 수 없는 일시 실패로 처리한다. 기존 재시도 정책에 따라 같은 `eventId`로 다시 보낸다.
- dev의 실제 전송과 운영 중 FCM 호출의 소요 시간, 타임아웃 횟수를 확인하고 필요할 때 값을 조정한다.

## 이유

[Firebase는 재시도 전에 전송 요청을 최소 10초 기다리라고 안내한다](https://firebase.google.com/docs/cloud-messaging/scale-fcm). 이는 연결과 쓰기를 각각 10초로 정하라는 뜻은 아니다. 하루들은 연결을 만들고 작은 요청을 보내는 단계는 오래 걸리지 않을 것으로 보고 각각 10초를 시작값으로 정했다. 요청을 받은 FCM이 처리한 뒤 응답을 돌려주는 시간은 더 걸릴 수 있으므로 응답 읽기는 30초를 준다. 이 값은 정상 응답을 너무 일찍 실패로 판단하지 않으면서, 응답이 오지 않을 때 워커가 계속 묶이지 않게 하려는 절충이다. 30초는 실측값이 아니라 시작 기준이며, 실제 전송 시간과 타임아웃 횟수를 보고 조정한다.

## 결과와 확인할 점

연결, 읽기, 쓰기 시간 제한은 **전송 전체에 걸리는 시간의 상한이 아니다**. SDK의 내부 재시도까지 포함한 실제 `send()` 시간이 5분 점유 시간에 가까워지는지 확인해야 한다. 점유 시간은 진행 중인 HTTP 호출을 중단하지 않는다.

타임아웃이 나도 FCM이 요청을 받았을 수 있다. 따라서 같은 작업을 재시도하면 같은 기기에 알림이 두 번 도착할 가능성은 남는다.
