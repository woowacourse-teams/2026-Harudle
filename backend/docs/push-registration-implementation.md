# 피드 푸시 등록은 현재 어떻게 저장되는가

이 문서는 현재 작성한 **푸시 등록 저장 코드**를 설명한다. 브라우저의 등록 요청을 받는 HTTP API, 로그인 세션 발급, FCM 알림 발송은 아직 연결하지 않았다.

## 등록할 때 사용하는 값

현재 저장 메서드는 아래 값을 받는다. 나중에 HTTP API를 연결할 때 `userId`와 `sessionId`는 브라우저가 보낸 본문이 아니라 인증 정보에서 가져와야 한다.

- `userId`와 `sessionId`: 등록을 요청한 사용자와 로그인 세션이다. 서버는 세션이 종료되지 않았고, 사용할 수 있는 Refresh Token이 있으며, 사용자가 탈퇴하지 않았는지 확인한다.
- `deviceId`: 같은 브라우저 환경의 등록을 다시 찾을 때 사용한다.
- `FID`: Firebase에 알림을 보낼 때 사용하는 값이다. 같은 환경에서도 바뀔 수 있다.
- 등록 ID와 `version`: 이미 등록한 FID를 바꿀 때 클라이언트가 알고 있는 현재 등록을 알려준다. 처음 등록할 때는 둘 다 보내지 않는다.

## 등록 요청을 처리하는 방법

| 현재 상태 | 저장 코드의 동작 |
| --- | --- |
| 이 `deviceId`에 등록이 없음 | 새 등록을 만들고 `version`을 `0`으로 둔다. |
| 같은 세션에서 같은 FID를 다시 등록 | 기존 등록을 그대로 반환한다. `version`은 올리지 않는다. |
| 같은 세션에서 FID가 바뀜 | 전달받은 등록 ID와 `version`이 DB와 같을 때만 FID를 바꾸고 `version`을 1 올린다. |
| 다른 유효한 세션이 `deviceId`나 FID를 사용 중 | 기존 등록을 유지하고 충돌을 알린다. 같은 사용자라도 세션이 다르면 이 규칙을 적용한다. |
| 이전 세션이 종료되었거나 만료됨 | 이전 등록과 보내지 않은 알림 작업을 취소한 뒤 새로 등록한다. |

같은 FID가 **같은 세션의 다른 `deviceId`**에 남아 있다면 이전 등록을 해제하고 새 `deviceId`로 등록한다. FID를 바꾸려는 요청의 등록 ID나 `version`이 오래된 값이면 DB를 바꾸지 않고 현재 등록 ID와 `version`을 알려준다. 예를 들어 FID가 `F2`로 바뀐 뒤 늦게 도착한 `F1` 요청은 `F2`를 다시 `F1`로 바꾸지 못한다.

## 등록을 해제할 때

요청한 세션이 소유한 `deviceId`의 등록만 해제한다. 아직 기다리는 `PENDING` 작업과 처리 중인 `PROCESSING` 작업은 같은 DB 트랜잭션에서 `CANCELLED`로 바꾼다. 이미 FCM이 수락한 것으로 기록된 `SENT` 작업은 그대로 둔다. 같은 해제 요청을 다시 보내도 추가 변경은 없다.

## 확인한 내용과 다음 작업

DB 통합 테스트 19개로 중복 요청, FID 변경 순서, 동시 요청, 세션 충돌, 만료된 세션의 교체, 등록 해제와 작업 취소를 확인했다. 다음 작업에서는 HTTP API가 인증된 사용자의 세션을 이 저장 코드에 전달하고, 충돌을 알맞은 HTTP 응답으로 바꿔야 한다. 로그아웃 처리와 FCM 발송 워커도 아직 구현 전이다. 진행 중인 등록 요청과 해제 요청이 겹치는 경우는 별도로 설계하고 검증해야 한다.
