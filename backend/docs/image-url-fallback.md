# 이미지 URL 발급 시 R2 원본 대체 조회

기존 일기 API가 이미지 URL을 발급하는 시점에 S3를 확인한다. 정상 객체는 S3 서명 URL을 반환하고, 객체가 없거나 S3 조회·서명 발급이 실패하면 R2 원본을 찾아 R2 서명 URL을 반환한다. 이미지를 내려받는 요청은 기존과 같이 브라우저가 직접 보낸다.

## 활성화와 적용 위치

`HARUDLE_GENERATION_ADAPTERS_ENABLED=true`와 `R2_ENABLED=true`일 때 `R2FallbackImageUrlProvider`가 기존 `ImageUrlProvider` 빈으로 등록된다. 추가 API나 프론트 수정은 필요하지 않다. R2가 비활성화되어 있으면 기존 S3 서명 URL 발급만 수행하며 존재 확인을 추가하지 않는다.

상세·생성·게스트·공유 응답의 `imageUrl`과 `imageUrlExpiresAt`, 월간 목록·연속 기록의 `thumbnailUrl`에 적용한다. 응답 필드와 DB 이미지 키는 유지한다. 일기 소유권, 게스트 세션과 공유 링크 유효성 검사가 끝난 뒤 기존 응답 조립 과정에서 URL을 발급한다. 사용자가 임의의 객체 키를 넘기는 새 엔드포인트는 만들지 않는다.

S3와 R2 환경이 다르면 서버 시작을 거절한다. `DEPLOY_ENV=dev`에서는 개발 경로만, `prod`에서는 운영 경로만 허용한다. 다른 환경, 참조 이미지와 잘못된 경로는 저장소 호출 전에 거절한다. 개발 서버에는 개발용 R2 자격 증명을 제공한다. R2 버킷은 비공개로 유지한다.

## 선택 순서

1. 현재 환경의 생성 이미지 키를 검증한다.
2. 응답에 사용할 S3 객체를 HEAD로 확인한다. 상세는 DB 키, 목록은 기존 변환 규칙에 따른 썸네일 키를 사용한다.
3. S3 객체가 존재하면 기존 S3 서명 URL을 발급한다. 정상 경로에서는 R2에 요청하지 않는다.
4. S3 객체가 없거나 조회·서명 발급에 실패하면 같은 폴더의 R2 원본 후보를 HEAD로 한 번 탐색한다. 요청 검증 오류는 R2로 우회하지 않는다.
5. 첫 번째 존재하는 원본의 R2 GET 서명 URL을 반환한다. 조회 권한·통신·설정 오류가 발생하면 종료하고, 다음 후보나 S3로 재시도하지 않는다.

| 입력 파일명 | R2 원본 후보 순서 |
| --- | --- |
| `image.png`, `image.jpg`, `image.webp` | 같은 키 하나 |
| `image-960.webp`, `image-240.webp` | 같은 폴더의 `image.png`, `image.jpg`, `image.webp` |

UUID 폴더가 하나인 기존 경로와 두 개인 현재 경로를 유지한다. 파생 이미지가 없는 R2에서 원본을 그대로 표시하며, 이 과정에서 다운로드·복사·재인코딩·DB 변경을 하지 않는다. MIME과 크기는 R2 원본 어댑터에서 검증한다. R2 서명 URL 유효기간은 `R2_ACCESS_URL_TTL`(기본 `15m`)을 따른다.

## 실패 응답과 로그

- S3가 실패했고 R2 원본 후보가 모두 없으면 HTTP 404 `IMAGE_BACKUP_NOT_FOUND`를 반환한다.
- R2 권한·인증·통신·설정 오류 등은 HTTP 503 `IMAGE_STORAGE_ERROR`로 반환한다. 저장소 오류를 백업 없음으로 처리하지 않는다.
- 기존 미인증·일기 권한 없음·일기 없음·공유 없음 응답을 유지하고, 해당 요청에서는 이미지 URL을 발급하지 않는다.

`event=image_url_selected`에 환경, 버킷, 대표 키, 선택한 원본 키, S3 결과·실패 유형, 최종 저장소 또는 실패 유형, MIME·크기와 소요 시간을 남긴다. 자격 증명, 서명 URL과 예외 원문은 남기지 않는다. DB 백업 기록 테이블을 추가하지 않는다.

## 범위와 확인 방법

이 방식은 URL 발급 시점의 존재·접근 확인이다. 이후 브라우저 GET의 오류, 시간 초과, URL 만료나 확인 직후 객체 삭제는 감지하지 못한다. HEAD가 성공한 객체의 실제 이미지 내용 손상도 확인하지 않는다.

R2 활성 시 이미지 URL 하나당 S3 HEAD가 추가된다. 누락된 후보는 R2 HEAD가 최대 세 번 추가되며, 본문 없는 404는 버킷 조회가 추가될 수 있다. 각 S3/R2 HEAD의 전체 제한은 10초이며, 목록의 여러 이미지는 기존 응답 조립 순서대로 처리한다. 한 이미지의 대체 조회까지 실패하면 현재 구조에서는 해당 목록·연속 기록 응답 전체가 오류로 종료된다.

개발 환경에서 접근 가능한 일기의 R2 원본이 있는 상태를 준비하고 다음을 확인한다. 정상 S3 조회에서는 R2 요청이 없어야 한다. S3 상세 또는 썸네일이 누락되면 같은 응답 필드에 R2 원본 URL이 반환되고 브라우저에서 표시되어야 한다. 양쪽 파일 부재는 404, R2 접근 오류는 503이어야 하며, 다른 사용자·만료된 게스트·없는 공유 링크는 URL 발급 전에 거절되어야 한다. S3 파일을 복구한 뒤에는 다시 S3 URL이 반환되어야 한다.

자동 테스트는 URL 선택, 원본 후보 변환, 환경 검증, 서명 URL 로그 배제, 기존 API 응답과 권한 차단을 확인한다. 실제 저장소 자격 증명·권한과 브라우저 표시 여부는 배포 환경에서 확인한다.
