# 이용약관 열람과 명시적 동의 (#428)

카카오로 본인을 확인한 뒤, 현재 이용약관을 직접 선택해 수락한다. 서버는 회원 ID와 문서 버전·내용 식별값·수락 시각을 기록한다. 로그인 성공이나 과거 가입일로 동의를 추정하지 않는다.

기준은 2026-10-25의 최신 develop-backend와 develop-frontend다. 사용자에게 제공받은 [기존 Notion 약관·개인정보처리방침](https://sun-acai-a8d.notion.site/409676b0adce8380b97101bd50ec7dd9)을 공개 문서 스냅샷으로 옮겼다. 본문의 사실 확인이 끝났다는 뜻은 아니다. [문서와 실제 처리의 대조](terms-policy-review.md)를 먼저 확인한다.

## 이번 구현의 경계

- OAuth와 Refresh Token의 기존 발급·회전은 유지한다. 미동의 회원도 본인 확인·문서 열람·동의 제출·로그아웃을 할 수 있다.
- 회원 서비스 API는 동의 검사를 별도로 적용한다. 관리자 제재가 우선하며, 미동의 회원은 403 TERMS_ACCEPTANCE_REQUIRED로 안내한다.
- 이용자는 약관 수락과 별도로 만 14세 이상임을 직접 확인한다. 서버도 이 항목을 검증하고 당시 기준 14를 기록한다. 생년월일을 추가 수집하거나 이를 신원·연령 인증으로 표현하지 않는다.
- 개인정보처리방침은 별도 고지문으로 보여준다. 그 문서 전체를 개인정보 수집·이용·국외 이전·분석 수집에 대한 일괄 동의로 취급하지 않는다.
- 개인정보처리방침의 버전·내용 식별값은 수락 당시 제시한 고지를 재현하기 위한 참조다. 개인정보처리방침만 변경됐다는 이유로 이용약관 재동의를 강제하지 않는다.
- 비로그인 공개 문서와 피드는 유지한다. 별도 쿠키로 동작하는 비회원 AI 체험의 동의 기록은 회원 Bearer 검사에 포함되지 않는다.
- 소셜 로그인은 이미 회원 정보를 생성한다. 이 구현을 “동의 전에 개인정보가 전혀 수집되지 않는 가입 방식”으로 설명하지 않는다.

## 문서와 수락 기록

약관은 2026-10-22, 개인정보처리방침은 2026-08-24를 최초 내부 버전 식별자로 사용한다. 원문에 별도의 버전 번호는 없었으며, 시행일은 원문에 적힌 날짜를 보존했다. 문서 내용의 기준은 2026-10-22 최종 편집된 원문을 2026-10-25에 가져온 스냅샷이다.

JSON 리소스의 UTF-8 바이트에 대한 SHA-256을 고정 manifest와 대조한다. 같은 버전의 글·공백을 바꾸면 시작 단계에서 실패한다. 공개한 버전을 고치지 말고 새 버전 파일을 추가한다. 현재 버전은 CURRENT_VERSIONS에서 선택하고, 과거 버전은 삭제하지 않아 해당 URL로 다시 읽을 수 있게 한다.

게시 버전과 서비스 접근에 인정할 수락 버전은 분리한다. ACCEPTED_TERMS_VERSIONS에는 현재 약관과 수락을 계속 인정할 과거 약관을 명시한다. 공지·오탈자 개정이면 기존 버전을 유지할 수 있고, 재동의가 필요한 개정이면 그 이전 버전을 제외한다. 어떤 개정에 재동의가 필요한지는 팀이 결정하며 날짜나 버전 문자열로 자동 판단하지 않는다. 배포 목록에 없는 버전을 인정하거나 현재 버전의 수락을 제외하는 설정은 시작 단계에서 거절한다.

수락 기록은 회원과 약관 버전별 한 행이다. 동시에 제출하거나 결과를 받지 못해 다시 제출해도 최초 시각을 덮어쓰지 않는다. 시각은 서버 Clock을 사용하며 요청에 회원 ID·시각·IP·User-Agent를 받지 않는다. 기존 회원의 기록을 채우는 데이터 전환은 없다.

상태 조회는 현재 약관 수락을 우선하고, 없다면 인정 목록에 적은 과거 버전 순서로 확인한다. 과거 수락으로 접근이 허용되더라도 현재 약관을 직접 선택해 제출하면 현재 버전의 이력을 별도로 저장한다. 과거 문서를 새로 제출하는 요청은 허용하지 않는다.

## API

| 요청 | 동작 |
| --- | --- |
| GET /api/v1/legal/documents | 현재 두 문서의 전문·버전·시행일·내용 식별값 |
| GET /api/v1/legal/documents/{terms 또는 privacy}/{version} | 해당 버전 전문. 존재하지 않으면 404 |
| GET /api/v1/me/agreements | 본인의 현재 수락 여부와 제시할 문서 참조 |
| PUT /api/v1/me/agreements | 명시적으로 선택한 현재 약관 수락. 최초 수락 시각 반환 |

개인 상태와 현재 문서 응답은 no-store다. PUT은 프로필 변경과 같은 기존 Bearer 전용 인증 방식을 따른다. CSRF가 필요한 Refresh·로그아웃 등 쿠키 API의 정책은 변경하지 않는다. 문서 버전·내용 식별값이 바뀌면 409 LEGAL_DOCUMENT_CHANGED로 거절하고 아무 기록도 추가하지 않는다. 화면은 최신 전문을 다시 읽고 선택을 초기화한다.

수락 요청에는 termsVersion, termsContentHash, privacyNoticeVersion, privacyNoticeContentHash, accepted: true, ageConfirmed: true를 보낸다. 화면에 표시한 문서의 식별값을 그대로 사용한다.

## 적용 순서

LEGAL_REQUIRE_TERMS_ACCEPTANCE의 기본값은 false다. 백엔드가 먼저 배포되더라도 기존 이용자의 API를 갑자기 막지 않는다.

1. [원문과 처리의 불일치](terms-policy-review.md)와 비회원 체험 안내를 팀에서 정리한다. 이용 연령은 사용자 결정에 따라 기존 만 14세 이상을 유지하며, 아동 이용과 보호자 동의는 후속 검토한다.
2. 백엔드 문서·수락 API를 배포하고, 프론트의 공개 열람·동의·세션 복원·거절 흐름을 배포한다.
3. 원문의 변경 안내 기준을 포함해 기존 이용자에게 적용할 안내와 시행일을 확정한다.
4. 신규·기존 계정으로 [상황별 흐름](terms-consent-scenarios.md)을 확인한 뒤 운영자가 환경별로 필수 적용을 켠다.

이 PR은 운영 환경 변수를 변경하거나 강제 적용을 켜지 않는다. 비활성화는 서비스 접근 제한만 해제하며 이미 저장한 수락 이력을 지우지 않는다.

이 적용은 회원 Bearer API의 약관 확인이다. 비회원 AI 체험의 안내·동의와 실제 개인정보 처리의 보유·파기·위탁 범위까지 완료된 것으로 취급하지 않는다. [정책 대조의 미확인 사항](terms-policy-review.md#운영-확인이-필요한-불일치)은 별도 정리 후 활성화한다.
