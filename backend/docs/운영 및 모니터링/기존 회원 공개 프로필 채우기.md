# 기존 회원 공개 프로필 채우기

기존 회원에게 없는 공개 닉네임과 기본 이미지를 채우는 수동 작업이다.
OAuth 이름(`users.name`)은 변경하지 않는다.

**배포만으로는 실행되지 않는다. 서버에서 직접 명령을 실행해야 한다.**

## 실행 순서

V22와 신규 가입 프로필 배정 코드 배포 -> 개발 서버에서 실행 및 확인 -> 운영 서버에서 실행 및 확인

```sh
# 개발 EC2에서 실행
sudo bash /opt/harudle/maintenance/run_profile_backfill.sh dev 100

# 운영 EC2에서 실행
sudo bash /opt/harudle/maintenance/run_profile_backfill.sh prod 100
```

`100`은 한 번에 처리할 회원 수다. 기본값은 100이며, 1~10,000을 지정할 수 있다.
예를 들어 350명이면 100명씩 세 번, 마지막에 50명을 처리하고 매번 저장한다.

지정한 환경이 서버의 `DEPLOY_ENV`와 다르면 실행을 중단한다.

## 처리 대상과 규칙

탈퇴 회원과 체험 회원은 제외한다. 만료된 체험 세션의 회원도 제외한다.

| 회원 상태 | 처리 |
|---|---|
| 닉네임과 이미지가 모두 없음 | 둘 다 배정 |
| 닉네임만 없음 | 닉네임만 배정 |
| 이미지만 없음 | 이미지만 배정 |
| 둘 다 있음 | 변경 없음 |

닉네임은 사용 가능한 후보에서 배정하고, 이미지는 코드 1~5 중 하나를 랜덤 배정한다. 기존 값은 유지한다.

## 실패하면

같은 명령을 다시 실행하면 된다. 이미 저장된 회원은 유지하고, 아직 값이 없는 회원만 처리한다.

실패한 배치는 저장되지 않는다. 잠금이나 후보 부족으로 처리하지 못한 회원이 있으면 오류를 출력하므로, 원인을 해결한 뒤 다시 실행한다.

## 실행 전후 확인

- 실행 전: 닉네임 후보 수(`available_candidates`)가 필요한 닉네임 수(`needs_nickname`)보다 충분한지 확인한다.
- 실행 후: 미처리 회원 수(`remaining_members`)와 닉네임 점유 불일치 수(`inconsistent_owners`)가 모두 **0**인지 확인한다.

사용할 SQL은 `backfill_user_public_profiles.sql`이다. 이전 `backfill_user_profile_images.sql`은 이미지만 채우므로 이번 작업에 사용하지 않는다.
