# 약관 동의의 상황별 흐름

전체 경계와 API는 [구현 설명](terms-consent.md), 원문의 확인 사항은 [정책 대조](terms-policy-review.md)를 참고한다.

## 1. 로그인과 기존 회원

~~~mermaid
flowchart TD
    A["카카오 본인 확인 또는 세션 복원"] --> B["서버에서 현재 약관 수락 상태 조회"]
    B --> C{"필수 적용 중이며 미수락인가?"}
    C -->|아니요| D["원래 화면 이용"]
    C -->|예| E["약관 확인 화면"]
    E --> F["직접 선택 후 서버에 수락 제출"]
    F --> G["버전·내용 확인과 최초 수락 시각 저장"]
    G --> D
~~~

기존 회원도 실제 이력이 없으면 미수락이다. 가입일이나 로그인 이력으로 동의 기록을 만들지 않는다. OAuth·Refresh Token을 막아 동의 화면에도 들어오지 못하는 순환을 만들지 않는다.

## 2. 동의 제출 실패와 문서 변경

~~~mermaid
flowchart TD
    A["동의하고 시작하기"] --> B{"서버 응답"}
    B -->|저장 완료| C["허용된 내부 화면으로 이동"]
    B -->|네트워크·일시 장애| D["선택 유지하고 재시도"]
    D --> A
    B -->|409 문서 변경| E["최신 전문 재조회"]
    E --> F["선택 초기화 후 다시 확인"]
    F --> A
~~~

중복 클릭은 화면에서 막고, 서버의 중복 저장 방지도 함께 둔다. 저장은 끝났지만 응답만 유실돼도 재시도로 최초 수락 시각이 바뀌지 않는다. 바뀐 문서를 자동으로 수락하지 않는다.

## 3. API 직접 호출과 제재

~~~mermaid
flowchart TD
    A["인증된 회원 API"] --> B{"관리자 제재 여부"}
    B -->|제재| C["403 계정 이용 제한"]
    B -->|정상| D{"필수 약관 미수락인가?"}
    D -->|예| E["403 약관 확인 안내"]
    D -->|아니요| F["기존 권한 검사와 API 처리"]
    D -->|조회 장애| G["500으로 거절"]
~~~

검사는 특정 피드·댓글 체인 하나에만 넣지 않는다. 일반 요청의 동의 조회에 사용자 행 잠금을 추가하지 않는다. 공개 문서, 본인 확인, 동의 조회·제출, 세션 정리 경로는 정확한 메서드와 경로로 예외 처리한다.

## 4. 공개 열람과 미동의 상태의 탈출

~~~mermaid
flowchart TD
    A["로그인·설정·랜딩의 문서 링크"] --> B["로그인 없이 전문·버전·시행일 열람"]
    B --> C{"문서 조회 결과"}
    C -->|성공| D["전문 표시"]
    C -->|일시 실패| E["화면 안에서 재조회"]
    C -->|없는 버전| F["현재 문서로 이동"]
~~~

로그인·공개 문서·동의 화면이 서로 무한 이동하지 않아야 한다. 외부 URL로 돌아가기와 로그인·동의 화면을 복귀 대상으로 사용하는 것은 허용하지 않는다. 비회원 AI 체험은 별도 쿠키 흐름이므로 이 회원 동의 검사만으로 보호자 동의나 AI 입력 동의까지 해결됐다고 설명하지 않는다.

## 5. 배포 순서

~~~mermaid
flowchart LR
    A["백엔드 배포 · 필수 적용 꺼짐"] --> B["프론트 배포 · 안내와 열람 확인"]
    B --> C["정책·시행일·기존 회원 안내 확정"]
    C --> D["환경별 필수 적용 켜기"]
~~~

기본 비활성 상태에서 약관 저장소 장애가 기존 회원 API를 막지 않는지도 검사한다. 켜진 상태의 장애는 “동의 안 함”으로 분류하지 않고 서버 오류로 거절한다.

## 6. 약관 개정과 기존 수락

~~~mermaid
flowchart TD
    A["새 버전 문서 추가 · 기존 전문 보존"] --> B{"이전 수락을 유지할 개정인가?"}
    B -->|공지·오탈자 등 유지 결정| C["현재 버전과 이전 버전을 인정 목록에 유지"]
    C --> D["기존 회원은 이전 수락으로 계속 이용"]
    B -->|중요 개정 · 재동의 결정| E["인정 목록에서 이전 버전 제외"]
    E --> F["기존 이력 보존 · 추가 수락 필요"]
    F --> G["현재 전문 확인 후 직접 수락"]
    D -->|현재 문서를 직접 수락하면| H["현재 버전 이력 별도 저장"]
    G --> H
~~~

현재 게시 문서와 수락을 인정하는 버전은 각각 명시한다. 유효한 이력이 여럿이면 현재 버전을 우선하며, 기록 시각이 더 늦다는 이유로 과거 버전을 선택하지 않는다. 개인정보 고지만 바뀌면 약관 재수락을 요구하지 않고 기존 수락 당시 고지 참조를 보존한다. 새 수락 요청은 언제나 현재 약관·현재 고지의 정확한 버전과 내용 식별값을 제출해야 한다.
