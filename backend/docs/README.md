# 백엔드 문서 가이드

백엔드 기능, 운영 방법, 설계 결정을 기록합니다.

# 문서를 작성하는 방법

1. 문서를 만들기 전에 기존 문서에 관련 내용이 있는지 확인합니다. 함께 읽어야 하는 내용이면 기존 문서에 추가합니다.
2. 기능의 동작과 API 요청 및 응답은 `명세`에 작성합니다. 운영 설정, 점검, 장애 대응과 복구 방법은 `운영 및 모니터링`에 작성합니다.
3. 문제를 해결할 방법을 선택한 이유는 `adr`의 주제별 폴더에 작성합니다. 자세한 기준과 양식은 [ADR 작성 가이드](adr/README.md)를 따릅니다.
4. 파일 이름은 내용을 알 수 있는 한국어로 작성합니다. API, DB, S3, R2처럼 널리 쓰는 이름은 그대로 사용합니다. ADR은 `날짜-제목-작성자.md`로 작성합니다.
5. 첫 부분에 무엇을 설명하는지 적고, 실제 동작이나 작업 순서를 쉬운 말로 설명합니다. 현재 동작과 과거 기록, 앞으로의 계획은 구분합니다.
6. API 문서에는 경로, 인증, 입력과 응답, 필요한 오류를 적습니다. 운영 문서에는 대상 환경, 실행 조건, 순서, 결과 확인과 실패 시 처리를 적습니다.
7. 필요한 관련 문서와 코드는 링크로 연결합니다. 같은 내용은 반복하지 않고, 비밀번호와 토큰 등 인증 정보는 적지 않습니다.
8. 핵심 내용을 먼저 적고, 필요한 내용을 설명합니다. 내용을 한눈에 찾을 수 있게 작성합니다.
9. 처리 순서나 구조를 글로 이해하기 어려우면 도식으로 표현합니다. 도식만으로 알기 어려운 내용은 글로 함께 설명합니다.
10. 5세도 이해할 수 있을 만큼 쉬운 말로 작성합니다. 읽는 사람이 내용을 쉽게 따라갈 수 있도록 짧은 문장과 여백과 적절한 줄바꿈을 사용합니다.
